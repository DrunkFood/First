# 业务文档编写指南

本文档说明如何为业务上下文 skill 编写高质量的知识文档。

## 核心原则

### 1. 只记录 AI 无法推断的知识

**应该记录的**：
- 业务规则和约定（如"Free 用户不包括 Trial 和 Lite"）
- 隐含的数据流和系统依赖
- 历史决策和遗留问题的背景
- 关键代码位置和入口点
- 团队约定和最佳实践

**不应该记录的**：
- 可以直接从代码中读取的信息
- 标准库或框架的使用方法
- 通用的编程知识
- 重复代码注释中已有的内容

### 2. 面向 AI 助手编写

记住文档的读者是 AI 助手，而非人类开发者：

| 人类开发者 | AI 助手 |
|-----------|--------|
| 需要背景故事 | 需要精确规则 |
| 喜欢示例代码 | 需要代码位置 |
| 可以记住上下文 | 每次对话独立 |

### 3. 提供可操作的信息

```
❌ "用户身份很重要"
✅ "判断用户身份使用 UserAttributeService.GetUserPayStatus()，位于 idecopilot/userattribute/service/service.go"
```

## 文档结构模板

### 概念型文档

```markdown
# {概念名称}

{一句话说明此概念的作用}

## 定义

| 字段/枚举 | 值 | 说明 |
|---------|---|------|
| Type1 | 0 | 说明 |
| Type2 | 1 | 说明 |

**代码位置**: `path/to/definition.go` - `TypeName`

## 使用规则

1. **规则一**: 说明
2. **规则二**: 说明

## 相关概念

- [概念A](./concept_a.md)
- [概念B](./concept_b.md)
```

### 流程型文档

```markdown
# {流程名称}

{一句话说明此流程的目的}

## 流程概览

```
步骤1 → 步骤2 → 步骤3 → 结果
```

## 详细步骤

### 1. {步骤名称}

**输入**: 参数说明
**输出**: 结果说明
**代码位置**: `path/to/handler.go` - `FunctionName`

### 2. {步骤名称}
...

## 异常处理

| 异常情况 | 处理方式 |
|---------|---------|
| 情况1 | 处理1 |
| 情况2 | 处理2 |
```

### 配置型文档

```markdown
# {配置名称}

{一句话说明此配置的作用}

## 配置项

| 字段 | 类型 | 默认值 | 说明 |
|-----|------|-------|------|
| FieldA | string | "" | 说明 |
| FieldB | int | 0 | 说明 |

**配置位置**: `lib/config/xxx.go` - `ConfigStruct`
**TCC 路径**: `namespace/config_name`

## 使用方式

```go
config := GetConfig()
value := config.FieldA
```

## 注意事项

- 注意点1
- 注意点2
```

## 写作规范

### 代码位置标注

始终提供精确的代码位置：

```markdown
**代码位置**: `idecopilot/aiusage/service/service.go` - `CheckEntitlement`
```

格式：`目录/文件.go` - `函数名/类型名`

### 表格使用

用表格呈现结构化信息：

```markdown
| 用户类型 | 枚举值 | 是否可跳过排队 |
|---------|-------|--------------|
| Free | 0 | ❌ |
| Pro | 1 | ✅ |
| Trial | 4 | ✅ |
```

### 关键词标注

在文档开头标注关键词，帮助 AI 定位：

```markdown
**关键词**: 计费、权益、quota、entitlement、billing
```

### 链接使用

使用相对路径链接到其他文档：

```markdown
详见 [用户身份](./user_identity.md)
参考 [开发规范](../references/development_guide.md)
```

## 反模式

### 1. 过于冗长

```
❌ 用户身份是一个非常重要的概念，它定义了用户的付费等级...
   在我们的系统中，用户身份会影响很多方面的行为...
   首先，让我们来了解一下历史背景...

✅ 用户身份（UserPayIdentity）定义用户付费等级，影响排队、模型选择等行为。
```

### 2. 缺少代码位置

```
❌ GetUserPayStatus 函数可以获取用户身份

✅ GetUserPayStatus 函数可以获取用户身份
   **代码位置**: `idecopilot/userattribute/service/service.go`
```

### 3. 重复代码注释

```
❌ // CheckQuota checks if user has enough quota
   func CheckQuota(...)
   
   文档中：CheckQuota 函数检查用户是否有足够配额

✅ 文档中：CheckQuota 在配额不足时会触发降级逻辑，优先使用缓存配额
```

### 4. 过时的信息

定期检查文档，删除或更新过时内容。在文档中标注可能变化的部分：

```markdown
> ⚠️ 此配置项可能在 v2.0 中变更，使用前请确认最新实现
```

## 文档维护

### 添加新文档

1. 确定文档属于哪个业务领域
2. 在 `_index.md` 中添加条目
3. 创建文档文件
4. 添加相关链接

### 更新现有文档

1. 更新内容
2. 检查是否需要更新 `_index.md`
3. 检查是否有其他文档引用了变更内容

### 删除过时文档

1. 从 `_index.md` 中删除条目
2. 删除文档文件
3. 更新引用此文档的其他文档
