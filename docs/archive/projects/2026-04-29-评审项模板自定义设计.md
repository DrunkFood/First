# 评审项模板自定义设计

## 背景

当前评审项的4种评审类型（符合性审查、技术标评审、资信标评审、商务评审）是硬编码的，AI 生成时固定输出全部类型。不同项目的模板对评审项的需求不同，需要模板管理员在配置模板时自定义评审项方案。

## 需求摘要

- 评审项配置属于模板本身，存储在 `sup_template` 和 `tb_project_template` 中
- 仅需两项配置：启用/禁用评审类型、启用/禁用评审标准
- 禁用评审标准时，`item_name` 自动填充 `"详见评审文件"`
- 使用 JSON 字段存储，无新增独立表
- 文档集成表格根据配置动态输出

## 1. 数据模型

### 1.1 表变更

**sup_template 新增字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `review_config` | JSON | 评审项配置 |

**tb_project_template 新增字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `review_config` | JSON | 评审项配置（模板快照） |

### 1.2 review_config JSON 结构

```json
{
  "reviewTypes": [
    {
      "reviewType": "COMPLIANCE",
      "enabled": true,
      "generateStandard": true
    },
    {
      "reviewType": "TECHNICAL",
      "enabled": true,
      "generateStandard": false
    },
    {
      "reviewType": "CREDIT",
      "enabled": false,
      "generateStandard": true
    },
    {
      "reviewType": "COMMERCIAL",
      "enabled": true,
      "generateStandard": false
    }
  ]
}
```

### 1.3 字段逻辑

| 字段 | 作用 |
|------|------|
| `enabled` | 控制该评审类型是否启用。AI 生成时只生成启用的类型，文档集成也只输出启用的类型表格，前端只显示启用的 Tab |
| `generateStandard` | 为 `false` 时，AI 不生成 `item_name` 和 `itemContent`，`item_name` 自动填充 `"详见评审文件"`，生成一个占位一级节点（保留分值，无子项） |

### 1.4 项目快照

创建项目时 `sup_template.review_config` 整体快照到 `tb_project_template.review_config`，后续项目独立使用快照值。

### 1.5 默认值

新建模板时4种类型全部 `enabled=true` + `generateStandard=true`，兼容现有行为。

## 2. AI 生成逻辑变更

### 2.1 改动点

1. **ReviewItemGenerator**：读取项目关联模板的 `review_config`，将其注入 User Prompt
2. **PromptTemplates.REVIEW_ITEM_GENERATE_USER**：新增参数，告诉 AI 只生成 `enabled=true` 且 `generateStandard=true` 的类型
3. **AiTaskResultSyncHandler.syncReviewItems**：同步结果时，对 `generateStandard=false` 的类型不依赖 AI 返回，直接插入占位节点

### 2.2 生成流程

```
提交AI生成评审项
  → 读取模板 review_config
  → 构建 Prompt: 只要求 AI 生成 enabled + generateStandard=true 的类型
  → AI 返回 JSON 结果
  → 同步到 tb_project_review_item
    → enabled=true, generateStandard=true: 正常同步 AI 返回的评审项
    → enabled=true, generateStandard=false: 插入占位节点（item_name="详见评审文件", 保留分值）
    → enabled=false: 跳过，不生成该类型
```

### 2.3 占位节点示例

| 字段 | 值 |
|------|-----|
| review_type | COMMERCIAL |
| level | 1 |
| item_name | 详见评审文件 |
| item_content | null |
| score | 该类型配置的分值（如有） |
| subjectivity | null |
| is_required | 0 |

## 3. 文档集成变更

### 3.1 改动点

1. **DocumentDataAssembler**：读取项目模板的 `review_config`，只组装 `enabled=true` 的评审类型表格
2. **汇总表**：只汇总启用的类型，分值合计只计算启用的类型
3. **占位类型表格**：`generateStandard=false` 的类型，表格只输出一行（"详见评审文件" + 分值）

### 3.2 数据 Key 策略

数据 Key 保持现有命名（`complianceItems`、`technicalItems`、`creditItems`、`commercialItems`、`allReviewItems`），未启用的类型不输出对应 Key。Word 模板中对应的行循环标签若无数据则不渲染，兼容现有模板。

## 4. 支撑中心模板管理变更

### 4.1 后端改动

1. **SupTemplate 实体**：新增 `reviewConfig` 字段
2. **TbProjectTemplate 实体**：新增 `reviewConfig` 字段（快照）
3. **模板新增/编辑接口**：支持保存 `reviewConfig`
4. **项目模板快照逻辑**：创建项目时 `reviewConfig` 随模板一起快照

### 4.2 前端改动

模板编辑页新增"评审项配置"区域：

```
评审类型          启用    生成评审标准
─────────────────────────────────
符合性审查         ☑        ☑
技术标评审         ☑        ☐
资信标评审         ☐        ☑
商务评审           ☑        ☐
```

### 4.3 交互规则

| 规则 | 说明 |
|------|------|
| 启用=关 | "生成评审标准"开关禁用变灰，该类型完全不参与评审 |
| 启用=开 | "生成评审标准"开关可选 |
| 默认值 | 新建模板时4种类型全部启用+全部生成评审标准 |
| 保存 | 前端将配置序列化为 `review_config` JSON 随模板一起提交 |

## 5. 项目端评审项阶段变更

### 5.1 改动点

1. **PhaseReviewItem.vue**：Tab 页从固定4个改为根据 `review_config` 动态渲染
2. **AI 生成请求**：前端提交生成时传递 `review_config`
3. **评分摘要栏**：只显示启用类型的分值

### 5.2 交互规则

| 场景 | 行为 |
|------|------|
| `enabled=true, generateStandard=true` | 正常 Tab，可 AI 生成、手动增删改 |
| `enabled=true, generateStandard=false` | Tab 显示，仅占位行（只读），"添加评审项"按钮隐藏 |
| `enabled=false` | Tab 不显示 |

### 5.3 占位 Tab 展示

`generateStandard=false` 的 Tab 下显示只读占位行，不可手动添加子项：

```
评审项名称      │ 评审内容 │ 分值 │ 主观/客观
详见评审文件     │    -     │  60  │     -

(未生成评审标准，不可手动添加)
```
