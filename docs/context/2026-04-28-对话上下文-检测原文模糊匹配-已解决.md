# 检测原文模糊匹配 - 对话上下文

> 生成时间: 2026-04-28 20:20 | 状态: 已解决

## 📋 问题背景

**项目**: 招标文件AI编制工具 (`tender-document-tool`)
**涉及模块**: `ele-ai-tender-file`(文件服务) + `ele-ai-tender-ai`(AI服务)
**当前状态**: 阶段A（规范化匹配）已实现并提交，阶段B（位置索引+前端高亮）待后续实施

智能检测功能中，`WordDocumentFixEngine` 使用 `String.contains()` 精确匹配 AI 返回的 `original` 原文与 Word 文档实际文本，因格式差异导致 >50% 的问题项匹配失败（`handleStatus=3`）。

## 🔴 核心问题

**问题表现**: 检测结果点击"接受"后，文档修复引擎找不到原文，无法自动替换

**根源分析**:
1. **Run 合并问题**: Word 同一段落由多个 Run 组成，提取纯文本和 `paragraph.getText()` 返回的文本之间有空格/换行差异
2. **AI 改写问题**: AI 模型返回 `original` 字段时，可能添加或删除了换行、空格

**具体数据**: 匹配失败率 >50%，涉及所有4种检测类型（敏感词/错别字/政策审查/格式检测）

## 🎯 实现目标

- 主要目标: 解决检测原文因空格/换行差异匹配失败的问题
- 具体要求: 两级匹配策略（精确→规范化），完全向后兼容
- 约束条件: 不改数据结构，不改接口签名，不改前端

## 🔧 技术约束

- 精确匹配优先，规范化匹配兜底
- `normalize()` 必须移除所有空白（不是合并），因为合并后 AI 添加的换行变成空格仍与无空格原文不一致
- `findActualOriginal()` 通过 `normToRaw[]` 位置映射还原原文实际范围，替换时用原始文本
- `isWhitespaceChar` 使用 ` ` / `　` 转义写法（字面量在源码中不可见，易误改）

## 🚫 已尝试的方案

1. **合并空白为单空格的 normalize** — 失败。AI 返回 `"招标\n文件"` 规范化后为 `"招标 文件"`（含空格），文档原文 `"招标文件"`（无空格），两者仍不匹配。必须移除所有空白才能消除差异。

## ✅ 当前方案（渐进式两阶段）

### 阶段A: 规范化模糊匹配 ✅ 已实现

**核心机制**:
```
Level 1: String.contains(original)  — 精确匹配，保留原逻辑
Level 2: normalize(text).contains(normalize(original))  — 规范化匹配
  → findActualOriginal() 通过 normToRaw[] 位置映射还原原文实际子串
  → doReplace() 用原始文本执行替换
```

**normalize 规则**: `text.replaceAll("[\\s\\u00A0\\u3000]+", "")` — 移除所有空白字符

**findActualOriginal 位置映射算法**:
```
1. 双方 normalize 后用 indexOf 找匹配位置 → normStart, normEnd
2. 构建 normToRaw[]: 逐字符推进原始文本，跳过空白字符，记录每个规范化字符在原始文本中的起始位置
3. rawText.substring(normToRaw[normStart], normToRaw[normEnd]) → 还原原文实际子串
```

## 💡 使用方法

无需额外配置，改动完全向后兼容：
- 精确匹配能命中的走 Level 1（行为不变）
- 精确匹配失败的自动走 Level 2 规范化匹配
- 规范化匹配也失败的仍返回 `handleStatus=3`

## 🐛 已知问题和待解决

1. **阶段B未实施**: 位置索引方案需要改数据结构（加 locationRef）、改 AI 提取逻辑、改前端高亮，工作量较大
2. **规范化匹配的误匹配风险**: 移除所有空白后，极短原文（如2-3个字）可能在文档多处匹配，但 `String.replace()` 会替换所有匹配项，这是原有行为
3. **Prompt 约束不可控**: AI 行为不可完全约束，Prompt 优化只是减少问题，不能消除

## 📝 备注

- **设计决策**: normalize 移除所有空白而非合并为单空格 — 中文文本中空格/换行通常是格式差异而非语义差异，移除后比较更准确
- **JDK 环境需显式设置**: `export JAVA_HOME="D:/Users/admin/.jdks/openjdk-21.0.5"`
- **踩坑**: `isWhitespaceChar` 中 U+00A0 字面量在源码中不可见，必须用 ` ` 转义；Java `\s` 不匹配 U+00A0 和 U+3000，normalize 正则需显式补充 `[\\s\\u00A0\\u3000]+`
