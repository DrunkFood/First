# 对话上下文：编辑器内检测高亮功能

> 生成时间：2026-04-23 | 状态：待确认

---

## 📋 问题背景

**项目**：招标文件AI编制工具（tender-document-tool）
**模块**：需求级智能检测 + 业务需求编辑器（WysiwygEditor）

需求智能检测对业务需求内容执行敏感词+错别字两项AI检测，用户可接受/拒绝建议。之前检测结果只在 `RequirementDetect.vue` 页面展示为卡片列表，用户无法在编辑器中直接看到问题位置。

**涉及组件**：
- 前端：`WysiwygEditor.vue`、`RequirementGenerate.vue`、`detection-highlight.ts`（新建）
- 类型：`DetectionIssueVO`、`RequirementDetectionRecord`

---

## 🎯 实现目标

在业务需求生成页面的 WysiwygEditor（TipTap）编辑器中，对已有检测结果的 `original` 文本显示高亮，悬浮时显示 reason 提示，让用户直接看到问题位置。

**具体要求**：
1. 高亮按 severity 分三级：HIGH（红色波浪线+浅红背景）、MEDIUM（橙色）、LOW（蓝色）
2. 只高亮 `handleStatus === 0`（未处理）的问题
3. 鼠标悬浮高亮文本时显示 reason 描述（`description` 字段）
4. 高亮需兼容暗黑/浅色主题
5. 内容编辑后高亮位置需自动重算

---

## 🔧 技术约束

- WysiwygEditor 使用 TipTap (vue-3)，内容以 Markdown 格式存储
- TipTap 基于 ProseMirror，需使用 `Decoration` API 添加视觉高亮（不修改文档内容）
- `@tiptap/pm` 提供 ProseMirror 的 `state`/`view` 模块，用于 Plugin/DecorationSet/Decoration
- TipTap 自定义命令必须通过 `declare module '@tiptap/core'` 增强到 `Commands<ReturnType>` 接口，否则 TS 报 `has no properties in common with type 'Partial<RawCommands>'`
- 内容通过 Markdown extension 双向转换，ProseMirror 文档树与 Markdown 源码位置不完全对应
- `original` 文本搜索仅在单个文本节点内匹配，跨 mark 节点的短语无法高亮（实际场景中 original 通常为短词，影响极小）

---

## ✅ 最终方案

### 核心机制

```
数据流：requirementApi.getDetectionRecords → 解析 result JSON → detectionIssues
       → WysiwygEditor highlights prop → setDetectionHighlights 命令
       → ProseMirror Plugin metadata → buildDecorations → DecorationSet
       → ProseMirror 渲染 inline decorations → CSS 高亮 + 悬浮提示
```

### 设计要点

1. **TipTap Extension**：创建 `DetectionHighlight` 扩展，使用 `addProseMirrorPlugins()` 注册 ProseMirror 插件
2. **Plugin state**：存储 `DecorationSet`，通过 `tr.getMeta(pluginKey)` 接收高亮数据更新
3. **命令更新**：`setDetectionHighlights` 命令通过 `dispatch(tr.setMeta(...))` 传递新数据，触发 plugin state `apply` 重建装饰
4. **文档变更**：`tr.docChanged` 时重建装饰（编辑后位置重算）
5. **非文档变更**：`oldSet.map(tr.mapping, tr.doc)` 映射位置（选区变化等不影响）
6. **CSS 悬浮提示**：`::after` 伪元素 + `attr(data-tooltip)` 读取属性值，`::before` 显示三角箭头
7. **模块增强**：`declare module '@tiptap/core'` 增强 `Commands` 接口，解决 TypeScript 类型检查

## 💡 使用方法

### WysiwygEditor 接收高亮数据

```vue
<WysiwygEditor
  v-model="content"
  :highlights="detectionIssues"
/>
```

`highlights` 类型为 `DetectionIssueVO[]`，仅 `handleStatus === 0` 且有 `original` 的项会生成高亮装饰。

### RequirementGenerate 加载逻辑

```typescript
// onMounted 中调用
loadDetectionHighlights(requirementId)

// 按类型去重取最新记录 → 解析 result JSON → 仅 COMPLETED 状态
```

### 高亮 CSS 类名

| severity | CSS 类 | 效果 |
|----------|--------|------|
| HIGH | `.detection-high` | 红色波浪下划线 + 浅红背景 |
| MEDIUM | `.detection-medium` | 橙色波浪下划线 + 浅橙背景 |
| LOW | `.detection-low` | 蓝色波浪下划线 + 浅蓝背景 |

悬浮提示内容取自 `data-tooltip` 属性（值为 `item.description`）。

## 🐛 已知问题和待解决

1. **跨 mark 文本无法高亮**：`original` 若跨越加粗/斜体等 mark 边界，ProseMirror 会拆为多个 text node，`indexOf` 无法匹配。实际场景中极少出现。
2. **同一段文字多次出现全部高亮**：`original` 在文档中多次出现时全部高亮，无法精确定位到 AI 指出的那一处。可用 `position` 字段辅助，但需额外实现。
3. **大文档性能**：`buildDecorations` 每次文档变更都全量遍历，极端情况下可能有性能问题。当前文档规模下无需优化。

## 📝 备注

- TipTap 自定义命令类型检查踩坑：必须用 `declare module '@tiptap/core'` 增强 `Commands<ReturnType>` 接口，否则 `addCommands` 返回的类型与 `Partial<RawCommands>` 不兼容（TS2322）
- 悬浮提示使用纯 CSS `::after` + `attr(data-tooltip)` 实现，无需额外 JS，但 `data-tooltip` 值需在 JS 中预拼接
- 用户已将 tooltip 内容简化为只显示 `description`（即 reason），去掉了 `targeted` 建议
- 高亮 CSS 使用 `var(--app-*)` 主题变量，兼容暗黑/浅色主题
