# 对话上下文：文档集成FillData格式标注渲染架构改造

> 生成时间：2026-04-28 20:30 | 状态：待确认

## 📋 问题背景

**项目**：招标文件AI编制工具（ele-ai-tender）
**涉及模块**：common / core / ai / file
**触发场景**：评审项方式一汇总表生成 Word 文档时，poi-tl 相邻标签合并 Bug 导致渲染失败

### 旧架构
```
core: DocumentDataAssembler → Map<String, Object>（扁平数据）
  → ai: DocumentIntegration → HTTP POST
    → file: WordDocumentServiceImpl → poi-tl {{?items}} 循环渲染 → POI 后处理合并单元格
```

**旧架构致命问题**：poi-tl 的 `refactorRun` 将相邻标签 `{{?allReviewItems}}{{categoryName}}` 合并为一个标签，导致报错 `Mismatched start/end tags`。已尝试6种修复方案均失败。

## 🔴 核心问题

| 问题 | 详情 | 状态 |
|------|------|------|
| poi-tl 相邻标签合并 Bug | `{{?items}}{{col}}` 被 refactorRun 合并为一个标签 | 新方案彻底绕开 |
| Word 模板标签碎片化 Run | Word/WPS 把标签拆成多个 Run + proofErr | WordTemplateEngine.acceptAllRevisions() 已解决 |
| LinkedHashMap 反序列化 | FillData.value 是 Object，JSON 反序列化后变成 LinkedHashMap | 已修复 |

## 🎯 实现目标

core 模块组装填充数据时标注每项格式类型（TEXT/TABLE/IMAGE），file 模块按类型选择生成方式：
- TEXT/IMAGE → poi-tl 渲染
- TABLE → POI 编程生成，彻底绕开 poi-tl 循环标签

## 🔧 技术约束

- poi-tl 必须用原生引擎 `Configure.builder().build()`，禁止 `useSpringEL()`
- poi-tl 版本 1.12.2，POI 版本 5.2.2，poi-ooxml-full 5.2.2
- POI 5.2.2 API：`XWPFDocument.insertNewTbl(XmlCursor)`（不是 `insertNewTable(int)`）
- XmlCursor 不是 AutoCloseable，需手动 `cursor.dispose()`
- JDK 21，Maven 多模块

## 🚫 已尝试的方案（旧方案，均已失败）

| 方案 | 结果 |
|------|------|
| POI 预拆分 Run + 不同 rPr（w:spacing） | refactorRun 忽略 rPr 差异 |

## ✅ 当前方案：FillData 格式标注 + 两阶段渲染

### 设计思路

```
core: DocumentDataAssembler → List<FillData>
  → ai: DocumentIntegration → HTTP POST (fillDataList)
    → file: WordDocumentServiceImpl
      ├─ 阶段一：分离数据 → poi-tl 渲染文本/图片（TABLE 放入 __TABLE_PLACEHOLDER__key 标记）
      └─ 阶段二：POI 打开渲染后文档 → 找 TABLE 标记段落 → TableGenerator 替换为 POI 生成的表格
```

### 核心机制

1. **数据分离**：FillData 按 type 分为三组
   - TEXT → `Map<String, String>` 传给 poi-tl
   - IMAGE → `PictureRenderData` 传给 poi-tl
   - TABLE → 占位符值 `__TABLE_PLACEHOLDER__key` + TableData 暂存

2. **两阶段渲染**：
   - 阶段一：poi-tl 渲染文本/图片，TABLE 占位符渲染为可见文本
   - 阶段二：POI 扫描 `__TABLE_PLACEHOLDER__xxx` 段落，用 TableGenerator 替换为完整表格

3. **表格生成**：TableGenerator 用 `insertNewTbl(XmlCursor)` 在占位段落位置插入表格，表头+数据行+合并单元格一步完成

4. **反序列化**：FillData.value 是 Object，JSON 传输后变 LinkedHashMap，需按 type 用 `ObjectMapper.convertValue()` 二次转换

### 模板占位符语法

| 类型 | 语法 | 渲染方式 |
|------|------|----------|
| 文本 | `{{projectName}}` | poi-tl 替换 |
| 表格 | `{{TABLE:allReviewItems}}` | 独立段落，POI 编程生成 |
| 图片 | `{{@sealImage}}` | poi-tl 图片渲染 |

## 📝 备注

### POI API 踩坑
- `XWPFDocument.insertNewTable(int)` 不存在，正确 API 是 `insertNewTbl(XmlCursor)`
- `XmlCursor` 不是 AutoCloseable（POI 5.2.2），需手动 `cursor.dispose()`
- `doc.removeBodyElement()` 后 `getPosOfParagraph()` 可能返回 -1

### JSON 反序列化踩坑
- `FillData.value` 声明为 `Object`，经 Jackson 序列化/反序列化后，`TableData` 和 `ImageData` 变为 `LinkedHashMap`
- 必须在 `deserializeFillDataList()` 中根据 `FillType` 用 `ObjectMapper.convertValue()` 二次转换
- 此问题在 file 模块和 ai 模块两处都需要处理
