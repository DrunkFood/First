# 对话上下文：文档集成FillData格式标注渲染架构改造

> 更新时间：2026-04-28 22:30 | 状态：待确认

## 📋 问题背景

**项目**：招标文件AI编制工具（ele-ai-tender）
**涉及模块**：common / core / ai / file
**触发场景**：评审项方式一汇总表生成 Word 文档时，poi-tl 相邻标签合并 Bug 导致渲染失败；后续又发现 `requirementContent` 含 Markdown 语法但只当纯文本渲染。

### 旧架构
```
core: DocumentDataAssembler → Map<String, Object>（扁平数据）
  → ai: DocumentIntegration → HTTP POST
    → file: WordDocumentServiceImpl → poi-tl {{?items}} 循环渲染 → POI 后处理合并单元格
```

**旧架构致命问题**：poi-tl 的 `refactorRun` 将相邻标签 `{{?allReviewItems}}{{categoryName}}` 合并为一个标签，导致报错 `Mismatched start/end tags`。已尝试6种修复方案均失败。

## 🔴 核心问题

| 问题 | 详情 | 状态 |
|------|------|------|
| poi-tl 相邻标签合并 Bug | `{{?items}}{{col}}` 被 refactorRun 合并为一个标签 | 新方案彻底绕开 |
| Word 模板标签碎片化 Run | Word/WPS 把标签拆成多个 Run + proofErr | WordTemplateEngine.acceptAllRevisions() 已解决 |
| LinkedHashMap 反序列化 | FillData.value 是 Object，JSON 反序列化后变成 LinkedHashMap | 已修复 |
| POI 生成的表格无边框 | `insertNewTbl(cursor)` 创建的表格默认无边框定义 | ✅ 已修复 |
| Markdown 内容当纯文本渲染 | `requirementContent` 含 `#`/`**`/`-`/`>` 等 Markdown 语法，poi-tl 只做字符串替换 | ✅ 已实现 |
| poi-tl 1.12.2 无 HtmlRenderPolicy | 原设计用 MD→HTML→HtmlRenderPolicy 路线，但 HtmlRenderPolicy 不存在于 1.12.2 | ✅ 已修正方案 |

## 🎯 实现目标

core 模块组装填充数据时标注每项格式类型（TEXT/TABLE/IMAGE/MARKDOWN），file 模块按类型选择生成方式：
- TEXT/IMAGE → poi-tl 渲染
- MARKDOWN → flexmark 解析 Markdown AST → DocumentRenderData → DocumentRenderPolicy 渲染为 Word 格式化段落
- TABLE → POI 编程生成，彻底绕开 poi-tl 循环标签

支持的 Markdown 语法：标题(h1-h6)、加粗、斜体、无序列表、有序列表、引用、代码/代码块

## 🔧 技术约束

- poi-tl 必须用原生引擎 `Configure.builder().build()`，禁止 `useSpringEL()`
- poi-tl 版本 1.12.2，POI 版本 5.2.2，poi-ooxml-full 5.2.2
- poi-tl 1.12.2 **没有** `HtmlRenderPolicy`（在 poi-tl-ext 中，未引入）
- poi-tl 有 `DocumentRenderPolicy` + `DocumentRenderData` 体系，可自定义渲染结构化文档内容
- flexmark-java 0.64.0 用于 Markdown AST 解析
- MARKDOWN 走阶段一（和 TEXT/IMAGE 一起由 poi-tl 渲染），不需要阶段二占位符
- POI 5.2.2 API：`XWPFDocument.insertNewTbl(XmlCursor)`（不是 `insertNewTable(int)`）
- XmlCursor 不是 AutoCloseable，需手动 `cursor.dispose()`
- `insertNewTbl` 创建的表格**默认无边框**，需通过 `CTTblBorders` 手动设置
- JDK 21，Maven 多模块

## ✅ 当前方案：FillData 格式标注 + 两阶段渲染 + Markdown AST 渲染

### 设计思路

```
core: DocumentDataAssembler → List<FillData>
  → ai: DocumentIntegration → HTTP POST (fillDataList)
    → file: WordDocumentServiceImpl
      ├─ 阶段一：分离数据 → poi-tl 渲染文本/图片/Markdown（TABLE 放入 __TABLE_PLACEHOLDER__key 标记）
      └─ 阶段二：POI 打开渲染后文档 → 找 TABLE 标记段落 → TableGenerator 替换为 POI 生成的表格
```

### 数据分离详情

```
core: DocumentDataAssembler → List<FillData>
  │
  ├─ TEXT     ──────────────────→ poiData["key"] = "纯文本"
  ├─ IMAGE    ──────────────────→ poiData["key"] = PictureRenderData
  ├─ MARKDOWN → MarkdownToDocumentConverter → poiData["key"] = DocumentRenderData
  │                                       markdownKeys.add("key")
  └─ TABLE    ──────────────────→ poiData["key"] = "__TABLE_PLACEHOLDER__key"
                                        tableDataMap["key"] = TableData
  │
  ▼
WordTemplateEngine.render(template, poiData, markdownKeys)
  ├─ Configure 为 markdownKeys 绑定 DocumentRenderPolicy
  └─ poi-tl 渲染：TEXT替换 + IMAGE + MARKDOWN→格式化Word段落 + TABLE占位文本
  │
  ▼
阶段二（仅 TABLE）：替换占位符为真实表格
```

### 核心机制

1. **数据分离**：FillData 按 type 分为四组
   - TEXT → `Map<String, String>` 传给 poi-tl
   - IMAGE → `PictureRenderData` 传给 poi-tl
   - MARKDOWN → `MarkdownToDocumentConverter` 转为 `DocumentRenderData` 传给 poi-tl
   - TABLE → 占位符值 `__TABLE_PLACEHOLDER__key` + TableData 暂存

2. **两阶段渲染**：
   - 阶段一：poi-tl 渲染文本/图片/Markdown，TABLE 占位符渲染为可见文本
   - 阶段二：POI 扫描 `__TABLE_PLACEHOLDER__xxx` 段落，用 TableGenerator 替换为完整表格

3. **Markdown 渲染**（MarkdownToDocumentConverter）：
   - flexmark 解析 Markdown → 遍历 AST 节点树 → 构建 `DocumentRenderData`
   - Heading → `ParagraphRenderData`（大号加粗字体：h1=22pt, h2=18pt, h3=15pt...）
   - Paragraph → `ParagraphRenderData`（含行内格式拆分：TextRenderData + Style）
   - BulletList/OrderedList → `NumberingRenderData`
   - BlockQuote → `ParagraphRenderData`（前缀 "> "）
   - StrongEmphasis → Style.bold=true
   - Emphasis → Style.italic=true
   - Code/CodeBlock → Courier New 等宽字体

4. **WordTemplateEngine**：为 markdownKeys 中的每个 key 绑定 `DocumentRenderPolicy`，poi-tl 自动将 `DocumentRenderData` 渲染为 Word 格式化段落

5. **表格生成**：TableGenerator 用 `insertNewTbl(XmlCursor)` 在占位段落位置插入表格，表头+数据行+合并单元格+边框一步完成

6. **反序列化**：FillData.value 是 Object，JSON 传输后变 LinkedHashMap，需按 type 用 `ObjectMapper.convertValue()` 二次转换
   - TEXT / MARKDOWN：value 是 String，无需转换
   - TABLE：value 用 `convertValue(typeRef)` 转为 TableData
   - IMAGE：value 用 `convertValue()` 转为 ImageData
   - switch 分支：`case TEXT, MARKDOWN` 同处理

### 表格生成详情

DocumentDataAssembler 生成 **5张表**：

#### 评审项分类表（4张，无合并）
`complianceItems` / `technicalItems` / `creditItems` / `commercialItems`

| 序号 | 评审项名称 | 评审项内容 | 分值 | 满分 | 权重 | 主观/客观 | 是否必审 |
|------|-----------|-----------|------|------|------|----------|---------|
| 1 | 资质要求 | ... | 5 | 20 | 0.2 | 客观 | 是 |
| 1.1 | 营业执照 | ... | 3 | - | - | 客观 | 是 |

8列，树形展平为单层行，多级序号（1, 1.1, 1.2, 2...），无合并规则。

#### 评审汇总表（1张，有合并）
`allReviewItems`

| 类别 | 评审标准 | 分值 | 主观/客观 |
|------|---------|------|----------|
| 资信标（20分） | 营业执照 | 5 | 客观 |
|  | 安全许可证 | 3 | 客观 |
| 技术标（50分） | 施工方案 | 20 | 主观 |

4列，`MergeRule(0, BY_SAME_TEXT)` 类别列相同文本纵向合并。类别顺序：资信标→技术标→商务标。

#### TableGenerator 样式
- 表格宽度 100%
- **边框**：6种（上下左右+内部横竖），SINGLE 单线，4号粗细，auto 颜色
- 字体：宋体 10号
- 表头：居中加粗
- 数据行：左对齐
- 单元格垂直居中，段落前后间距 0

### 模板占位符语法

| 类型 | 语法 | 渲染方式 |
|------|------|----------|
| 文本 | `{{projectName}}` | poi-tl 替换 |
| 表格 | `{{TABLE:allReviewItems}}` | 独立段落，POI 编程生成 |
| 图片 | `{{@sealImage}}` | poi-tl 图片渲染 |
| **Markdown** | `{{requirementContent}}` | flexmark→DocumentRenderData→DocumentRenderPolicy |

### 如何添加新的 Markdown 字段

1. 在 `DocumentDataAssembler.assemble()` 中使用 `FillData.markdown("key", value)` 而非 `FillData.text()`
2. 模板中放 `{{key}}` 占位符（独立段落）
3. 渲染时自动通过 MarkdownToDocumentConverter 转换

## 📝 备注

### POI API 踩坑
- `XWPFDocument.insertNewTable(int)` 不存在，正确 API 是 `insertNewTbl(XmlCursor)`
- `XmlCursor` 不是 AutoCloseable（POI 5.2.2），需手动 `cursor.dispose()`
- `doc.removeBodyElement()` 后 `getPosOfParagraph()` 可能返回 -1
- **`insertNewTbl` 创建的表格默认无边框**，必须通过 `CTTblBorders` 设置 6 种边框（top/bottom/left/right/insideH/insideV）

### JSON 反序列化踩坑
- `FillData.value` 声明为 `Object`，经 Jackson 序列化/反序列化后，`TableData` 和 `ImageData` 变为 `LinkedHashMap`
- 必须在 `deserializeFillDataList()` 中根据 `FillType` 用 `ObjectMapper.convertValue()` 二次转换
- 此问题在 file 模块和 ai 模块两处都需要处理
- TEXT / MARKDOWN 的 value 是 String，反序列化后仍为 String，无需 convertValue

### poi-tl Markdown 踩坑
- **poi-tl 1.12.2 没有 HtmlRenderPolicy**：该类在 poi-tl-ext 扩展包中，核心包只有 DocumentRenderPolicy。设计时须验证 API 可用性
- **DocumentRenderPolicy + DocumentRenderData 是正确路线**：不经过 HTML 中间步骤，直接从 AST 构建 poi-tl 数据模型，渲染更可控
- **ConfigureBuilder 需要直接 import**：`Configure.builder()` 返回的是 `ConfigureBuilder`（非内部类），需要 `import com.deepoove.poi.config.ConfigureBuilder`
