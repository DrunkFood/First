# 对话上下文：模板卡片移除文档结构树与刷新消失修复

> 生成时间：2026-04-23 | 状态：已解决

---

## 📋 问题背景

**项目**: 招标文件AI编制工具 (ele-ai-tender)
**涉及模块**: ele-ai-tender-frontend（AI编制业务前端）
**涉及页面**: 项目管理基础信息录入页面 (`/project/:id/wizard?step=0`)

用户提出两个需求/问题：
1. 模板卡片中无需展示文档结构树（el-tree），只保留占位符标签
2. 页面刷新后模板卡片消失的 Bug

---

## 🔴 核心问题

### 问题1：模板卡片展示过多信息
模板选择卡片中用 `el-tree` 展示了 Word 文档的章节结构树，用户认为无需在此处展示。

### 问题2：刷新后模板消失（Bug）
**表现**: 基础信息页面刚进入时能看到项目模板，刷新页面后模板消失。

**根因**: 竞态条件——`onMounted` 依据 `props.readonly` 的初始快照决定加载哪个数据源，但 `readonly` 由父组件异步计算：
1. 组件挂载时 `phaseStep = 0`（初始值），`readonly = false`
2. `onMounted` 执行：`readonly` 为 `false`，只调用 `loadTemplates()`
3. 父组件 `ProjectWizard.loadProject()` 异步完成，更新 `phaseStep = 1`（项目已过基础信息阶段）
4. `readonly` 响应式变为 `true`
5. computed `displayTemplateList` 切换到读取 `projectTemplateSnapshot`——但 `loadProjectTemplate()` 从未执行
6. 结果为空，模板消失

---

## 🎯 实现目标

1. 模板卡片中移除文档结构树展示，保留占位符标签
2. 预览弹窗中用 Word 文档实时预览替代文档结构树
3. 修复刷新后模板消失的竞态 Bug

---

## 🔧 技术约束

- 前端框架：Vue 3 + TypeScript + Element Plus
- 模板数据：`templateApi.getList()` 返回全量模板，`projectTemplateApi.getByProject()` 返回项目绑定模板快照
- Word 预览：项目已有 `DocxPreview` 组件（基于 docx-preview 库），接收 `fileId` 渲染
- 模板实体含 `fileId` 字段，可直接用于 DocxPreview

---

## ✅ 最终方案

### 1. 移除模板卡片中的文档结构树
- 删除模板卡片中 `el-tree` 及 `div.tpl-structure` 代码块
- 删除 `buildTreeData()` 函数（不再有调用方）
- 移除 `WordChapter` 类型导入
- 移除 `.tpl-structure` CSS 样式

### 2. 预览弹窗改用 Word 文档预览
- 将弹窗中的 `el-tree` 文档结构树替换为 `<DocxPreview :file-id="previewTemplate.fileId" />`
- 有 `fileId` 时渲染 Word 文档，无 `fileId` 且无 `content` 时显示空状态
- 弹窗宽度从 60% 调整为 80%（适配文档预览）
- 保留用途说明、占位符标签、书签展示
- 移除 `.preview-structure` CSS 样式

### 3. 修复刷新后模板消失
- `onMounted` 始终同时调用 `loadTemplates()` 和 `loadProjectTemplate()`
- 不再依赖 `props.readonly` 的初始快照做条件加载
- `displayTemplateList` computed 仍根据 `readonly` 选择数据源，但两个数据源都已就绪

## 📝 备注

**竞态 Bug 教训**：当子组件的 `onMounted` 逻辑依赖父组件异步计算出的 prop 时，不能只看 prop 的初始值做一次性决策。应始终加载所有可能用到的数据，或使用 `watch` 监听 prop 变化后补充加载。

- `ele-ai-tender-frontend/src/components/document/DocxPreview.vue` — Word 文档预览组件
- `ele-ai-tender-frontend/src/api/template.ts` — 模板 API
