# 对话上下文文档：评审项模板自定义

> 生成时间：2026-04-29 | 状态：待确认

---

## 📋 问题背景

**项目**：招标文件AI编制工具（tender-document-tool）
**涉及模块**：支撑中心(support)、核心业务(core)、AI服务(ai)、双前端项目
**当前状态**：评审项的4种评审类型（符合性审查、技术标评审、资信标评审、商务评审）是硬编码的，AI生成时固定输出全部类型，无法根据模板自定义

**触发需求**：评审项生成和文档集成评审项目表格需要根据模板自定义调整——哪些评审类型需要、是否生成评审标准、是否分主观客观

---

## 🔴 核心问题

1. AI Prompt 固定要求生成4种评审类型，无法按模板配置只生成部分类型
2. 文档集成固定输出5个表格（4种类型+汇总），无法按配置动态输出
3. 前端评审项页面固定4个Tab，无法按配置动态渲染
4. 部分项目不需要某些评审类型的详细标准，只需占位提示

---

## 🎯 实现目标

在模板中新增 `review_config` JSON 配置字段，控制：
- **启用/禁用评审类型**：不启用的类型不生成、不输出、不显示
- **启用/禁用评审标准**：generateStandard=false 时，item_name 填充"详见评审文件"，生成占位一级节点
- 贯穿支撑中心配置→项目快照→AI生成→文档集成→前端展示全链路

**约束条件**：
- 评审项配置属于模板本身（非独立实体），存储在 sup_template 和 tb_project_template 中
- 使用 JSON 字段存储，无新增独立表
- 向后兼容：reviewConfig 为 null 时回退到全部启用的默认行为

## 🚫 已尝试的方案

| 方案 | 结果 | 原因 |
|------|------|------|
| 方案A：评审方案单实体（2张表+JSON类型配置） | 放弃 | 类型配置用JSON无法SQL查询 |
| 方案B：方案+类型配置分离（3张表） | 放弃 | 用户调整为"配置属于模板本身" |
| 方案C：全JSON（1张表） | 放弃 | 默认评审项嵌在JSON里无法查询 |
| 独立评审方案+模板引用 | 放弃 | 用户改为"配置属于模板本身" |
| 预设默认评审项 | 放弃 | 用户简化需求，取消该功能 |
| AiTask.extParams 传递 reviewConfig | 放弃 | AiTask 实体无 extParams 字段，改用 requestParams 兜底 |

---

## ✅ 最终方案

**方案**：在 sup_template 和 tb_project_template 新增 review_config JSON 字段，配置内容为：

```json
{
  "reviewTypes": [
    {"reviewType": "COMPLIANCE", "enabled": true, "generateStandard": true},
    {"reviewType": "TECHNICAL", "enabled": true, "generateStandard": false},
    {"reviewType": "CREDIT", "enabled": false, "generateStandard": true},
    {"reviewType": "COMMERCIAL", "enabled": true, "generateStandard": false}
  ]
}
```

**核心机制**：
1. 支撑中心模板编辑页配置 → JSON存入 sup_template.review_config
2. 项目绑定模板时快照到 tb_project_template.review_config
3. AI 生成时读取配置 → 只生成 enabled+generateStandard=true 的类型
4. 结果同步时：过滤AI违规返回 + 为 generateStandard=false 插入占位节点
5. 文档集成时：只输出启用类型的表格
6. 前端：动态Tab + 占位只读展示

## 💡 使用方法

### 1. 执行数据库变更
```sql
ALTER TABLE sup_template ADD COLUMN review_config JSON DEFAULT NULL COMMENT '评审项配置JSON' AFTER structure_definition;
ALTER TABLE tb_project_template ADD COLUMN review_config JSON DEFAULT NULL COMMENT '评审项配置JSON(快照)' AFTER structure_definition;
```

### 2. 编译部署
```bash
# 安装 common 模块（必须用 JDK 21）
cd ele-ai-tender-system
export JAVA_HOME="D:/Users/admin/.jdks/openjdk-21.0.5"
mvn install -pl ele-ai-tender-common -am -Dmaven.test.skip=true
mvn compile -pl ele-ai-tender-core,ele-ai-tender-ai -am -Dmaven.test.skip=true
```

### 3. 验证流程
1. 支撑中心：编辑模板 → 评审项配置区域 → 关闭某类型启用/评审标准 → 保存
2. 编制前端：创建项目绑定模板 → 进入评审项阶段 → 确认Tab动态显示 → AI生成 → 确认占位节点
3. 文档集成：生成文档 → 确认只输出启用的类型表格

### 注意事项
- 旧模板 reviewConfig 为 null，全链路自动回退到"全部启用"，无需迁移
- 关闭启用时前端自动重置 generateStandard=true
- AI可能违规返回未启用类型，syncHandler 已做 removeIf 过滤
