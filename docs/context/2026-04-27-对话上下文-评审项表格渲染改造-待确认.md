# 对话上下文：评审项表格渲染改造

> 状态：**待确认** | 日期：2026-04-27

---

## 📋 问题背景

**项目**：招标文件AI编制工具（ele-ai-tender）
**模块**：ele-ai-tender-core（核心业务 :8082）→ ele-ai-tender-file（文件服务 :8081）
**涉及组件**：DocumentDataAssembler（数据组装）→ WordTemplateEngine（poi-tl模板渲染）

`DocumentDataAssembler` 将评审项数据转为扁平 Map 列表供 poi-tl 填充 Word 模板，但原始实现存在三个缺陷，导致评审项无法正确以表格形式展示在生成的 Word 文档中。

---

## 🔴 核心问题

| 问题 | 详情 |
|------|------|
| **字段不完整** | `toFlatList()` 仅映射 4 字段（itemName/itemContent/score/level），遗漏 maxScore/weight/subjectivity/isRequired |
| **无树形结构** | `parentId`+`level` 信息被丢弃，1级分类和2级评审项混在一起，无序号无缩进 |
| **嵌套结构阻碍模板** | 评审项列表嵌套在 `reviewData` Map 下，poi-tl `{{#listName}}` 标签只能访问顶层 key |

原始 `toFlatList()` 代码：
```java
// 旧实现 - 仅4字段，无树形结构
return items.stream().map(item -> {
    Map<String, String> map = new LinkedHashMap<>();
    map.put("itemName", item.getItemName());
    map.put("itemContent", item.getItemContent());
    map.put("score", String.valueOf(item.getScore()));
    map.put("level", String.valueOf(item.getLevel()));  // level只当字符串输出，无实际用途
    return map;
}).toList();
```

---

## 🎯 实现目标

评审项在 Word 文档中以标准表格展示：
- **多级序号**：1 → 1.1 → 1.1.1 → ...（支持任意层级递归）
- **层级缩进**：层级越深，itemName 前的全角空格越多
- **分类行 vs 叶子行**：非叶子节点填充分类维度字段（maxScore/weight），叶子节点完整填充所有 8 字段
- **4种评审类型各一个独立表格**：COMPLIANCE / TECHNICAL / CREDIT / COMMERCIAL

## 🔧 技术约束

| 约束 | 说明 |
|------|------|
| **poi-tl 原生引擎** | 必须用 `Configure.builder().build()`，**禁止 `useSpringEL()`**（SpringEL 对 Map 数据不友好，缺失字段抛 SpelEvaluationException） |
| **数据结构** | 全部为 `Map<String, Object>` + `List<Map<String, String>>`，原生引擎通过 `Map.get()` 访问 |
| **poi-tl 版本** | 1.12.2（父 POM `${poi-tl.version}`），必须 ≥ 1.12.2 |
| **无需自定义 RenderPolicy** | poi-tl 原生引擎已内置 `{{#list}}` 行循环，无需注册 LoopRowTableRenderPolicy 等自定义策略 |
| **修订标记预处理** | WordTemplateEngine.render() 在传给 poi-tl 前必须 `acceptAllRevisions()` |

### 关键文件

| 文件 | 角色 |
|------|------|

| 方案 | 结果 | 原因 |
|------|------|------|

## ✅ 当前方案（递归多级）

### 设计思路

1. `toFlatList()` 构建 `parentId→children` 映射
2. 筛选根节点（parentId==null 或 0），按 sortOrder 排序
3. 递归调用 `flattenNode()` 前序遍历，生成有序扁平列表
4. 序号自动拼接：`1` → `1.1` → `1.1.1`...
5. 缩进按 depth 递增：depth=1 无缩进，depth=2 两个全角空格，depth=3 四个
6. 有子节点 = 非叶子行（只填 maxScore/weight）；无子节点 = 叶子行（全字段填充）

### 核心机制

```
toFlatList(items)
  ├─ 构建 childrenMap: parentId → List<TbProjectReviewItem>
  ├─ 筛选 roots: parentId == null/0, 按 sortOrder 排序
  └─ 遍历 roots → flattenNode(root, "1", 1, childrenMap, result)

flattenNode(node, serialNo, depth, childrenMap, result)
  ├─ hasChildren? → 分类行(只填maxScore/weight) : 叶子行(全字段)
  ├─ result.add(当前节点Map)
  └─ 递归子节点: flattenNode(child, "1.1", 2, ...)
```

### assemble() 数据结构变更

```java
// 改动前（嵌套）
Map<String, Object> reviewData = new LinkedHashMap<>();
reviewData.put("complianceItems", toFlatList(...));
// ...
data.put("reviewData", reviewData);

// 改动后（顶层）
data.put("complianceItems", toFlatList(...));
data.put("technicalItems", toFlatList(...));
data.put("creditItems", toFlatList(...));
data.put("commercialItems", toFlatList(...));
```

### 每行 Map 字段（8 个）

| 字段 | 非叶子行 | 叶子行 |
|------|---------|--------|
| `serialNo` | ✅ "1" / "1.2" | ✅ "1.2.1" |
| `itemName` | ✅ 无缩进 | ✅ 有缩进前缀 |
| `itemContent` | 空 | ✅ |
| `score` | 空 | ✅ |
| `maxScore` | ✅ | ✅ |
| `weight` | ✅ 带"%" | ✅ 带"%" |
| `subjectivity` | 空 | ✅ "客观"/"主观" |
| `isRequired` | 空 | ✅ "是"/"否" |

## 💡 使用方法

### Word 模板占位符设计

模板中每种评审类型对应一个独立表格，以技术标为例：

**表头行**：
| 序号 | 评审项名称 | 评审内容 | 分值 | 满分 | 权重 | 主/客观 | 必审 |

**数据行**（在 Word 模板中填写）：
| `{{#technicalItems}}{{serialNo}}` | `{{itemName}}` | `{{itemContent}}` | `{{score}}` | `{{maxScore}}` | `{{weight}}` | `{{subjectivity}}` | `{{isRequired}}{{/technicalItems}}` |

4 个表格标签：
- `{{#complianceItems}}` ... `{{/complianceItems}}`
- `{{#technicalItems}}` ... `{{/technicalItems}}`
- `{{#creditItems}}` ... `{{/creditItems}}`
- `{{#commercialItems}}` ... `{{/commercialItems}}`

### 注意事项
1. `{{#listName}}` 放在数据行第一个单元格，`{{/listName}}` 放在最后一个单元格
2. 行循环标签仅支持**顶层 key**，不支持 `reviewData.technicalItems` 嵌套路径
3. 模板编辑后需关闭修订追踪，或由 WordTemplateEngine 的 `acceptAllRevisions()` 自动处理

## 📝 备注

### 经验教训
- poi-tl 原生引擎 `{{#list}}` 是内置标签，无需注册 RenderPolicy，`LoopRowTableRenderPolicy` 是手动绑定场景用的
- 原生引擎数据访问走 `Map.get()`，缺失字段返回空字符串天然容错；SpringEL 走反射 getter，缺失字段抛异常
- 评审项树形结构用 `parentId→children` 映射 + 递归前序遍历是最简方案，避免引入额外树结构库
