> 生成时间: 2026-04-23

---

## 📋 问题背景

**项目**: 招标文件AI编制工具（ele-ai-tender）
**涉及模块**: ele-ai-tender-common / ele-ai-tender-file / ele-ai-tender-core / ele-ai-tender-support / 两个前端项目
**原状态**: 模板以 Markdown 格式存储和编辑，项目直接外键引用 sup_template，文档生成硬编码 Markdown，三者均不满足业务需求。

### 涉及组件

| 组件 | 端口 | 角色 |
|------|------|------|
| ele-ai-tender-support | 8080 | 模板配置管理（上传Word模板） |
| ele-ai-tender-file | 8081 | 文件存储 + Word解析/生成 |
| ele-ai-tender-core | 8082 | 项目管理 + 文档集成 |
| ele-ai-tender-support-frontend | 3060 | 支撑中心管理后台 |
| ele-ai-tender-frontend | 5173 | AI编制业务前端 |

---

## 🔴 核心问题

1. **模板格式不适用**: sup_template.content 存 Markdown，但业务需要 Word 模板预留占位符
2. **项目与模板耦合**: tb_project.template_id 直接外键引用 sup_template，模板变更影响已有项目
3. **文档生成硬编码**: DocumentIntegrationServiceImpl.buildMarkdownDocument() 硬编码生成 Markdown

---

## 🎯 实现目标

1. sup_template 新增 fileId 关联 Word 文件，content 改为用途说明，structureDefinition 改为 Word 章节结构 JSON
2. 新建 tb_project_template 表存储项目模板快照，只读不可修改，与 sup_template 隔离
3. 文档生成改为 Word 模板填充：poi-tl 填充 {{变量名}} + Word 书签
4. Word 章节结构解析和文档生成引擎放在 File 服务
5. 支撑前端从 Markdown 编辑改为 Word 文件上传

---

## 🔧 技术约束

- **JDK 21**，Spring Boot 3.2.2，MyBatis-Plus 3.5.5
- **poi-tl 1.12.0** 已在父 POM dependencyManagement 中管理
- **表前缀规范**: tb_(核心) / ai_(AI服务) / sup_(支撑) / file_(文件)
- **实体继承 BaseEntity**（自动填充 create/modify 时间、ver、is_delete）
- **BaseEntity 的 @TableLogic** 导致 delete() 是逻辑删除，唯一约束释放需物理删除
- **编译**: 必须用 JDK 21，`export JAVA_HOME="D:/Users/admin/.jdks/openjdk-21.0.5"`
- **common 变更后必须 install**: `mvn install -pl ele-ai-tender-common -am`
- **poi-tl 引擎**: 必须使用原生引擎（非 SpringEL），SpringEL 用反射访问属性对 Map 不友好

## 🚫 已尝试的方案

### 设计阶段方案评估

| 方案 | 描述 | 结论 |
|------|------|------|
| 方案A: 最小改动 | sup_template 新增字段+新建表，不改跨模块调用关系 | **采用** |
| 方案B: 模板服务统一 | 将模板 CRUD 统一到 Support，Core 通过 HTTP 调用 | 放弃，引入跨模块HTTP调用复杂度 |

文档生成引擎位置评估：

| 位置 | 结论 |
|------|------|
| 留在 Core | 放弃，需先下载模板再填充再上传，多次网络传输 |
| 移至 File | **采用**，File 本地直接读模板文件，零网络开销 |

### 端到端验证中失败的方案

| 方案 | 描述 | 失败原因 |
|------|------|------|
| WordTemplateEngine 使用 useSpringEL() | 启用 poi-tl 的 SpringEL 引擎 | **失败** — SpringEL 通过反射访问属性，对 Map 类型数据不友好，缺失字段抛 SpelEvaluationException |
| LenientMap 包装 | 继承 HashMap 覆写 get() 返回空字符串 | **失败** — SpringEL 不调用 Map.get()，而是用反射查找属性方法 |

## ✅ 最终方案

### 核心机制

```
支撑中心上传Word模板 → sup_template(fileId + 用途说明 + 章节结构)
                              ↓
项目创建选模板 → 复制快照到 tb_project_template（只读隔离）
                              ↓
文档生成 → Core组装扁平数据 → File服务poi-tl填充 → 返回generatedFileId
```

### 数据库变更

- sup_template: 新增 file_id BIGINT, content 改可空, structure_definition 语义变更
- tb_project_template: 新建，uk_project_id 唯一约束（一个项目一个模板）
- tb_project.template_id: 语义从关联 sup_template 改为关联 tb_project_template

### File 服务新增

- WordStructureParser: 解析 Word 章节/占位符/书签，正则支持中文 `\{\{([\w一-龥]+)}}`
- WordTemplateEngine: poi-tl XWPFTemplate.compile().render()，**使用原生引擎**（非 SpringEL）
- FileController: GET /api/file/structure/{fileId}, POST /api/file/generate-doc

### 关键设计决策

- **快照策略**: 项目绑定模板时复制元数据+fileId引用，不复制文件物理副本
- **物理删除**: ProjectTemplateMapper 新增 `physicalDeleteByProjectId()` 使用 @Delete 原生SQL，绕过 @TableLogic
- **扁平化**: DocumentDataAssembler 评审项从 List<TbProjectReviewItem> 转为 List<Map<String, String>>
- **结构解析时机**: Support 模块 create/update 模板时自动调用 File 服务解析 Word 结构
- **poi-tl 原生引擎**: 不使用 SpringEL，原生引擎通过 Map.get() 访问数据，缺失字段返回空字符串不报错

## 💡 使用方法

### 1. 安装公共模块

```bash
export JAVA_HOME="D:/Users/admin/.jdks/openjdk-21.0.5"
cd ele-ai-tender-system && mvn install -pl ele-ai-tender-common -am -Dmaven.test.skip=true
```

### 2. 启动服务（按顺序）

```bash
cd ele-ai-tender-file && mvn spring-boot:run       # :8081
cd ele-ai-tender-support && mvn spring-boot:run     # :8080
cd ele-ai-tender-core && mvn spring-boot:run        # :8082
```

### 3. API 端点

| 服务 | 端点 | 方法 | 说明 |
|------|------|------|------|
| Support | /api/v1/template-configs | POST | 创建模板（含fileId自动解析结构） |
| Support | /api/v1/template-configs | GET | 查询模板列表 |
| File | /api/file/upload | POST | 上传Word文件 |
| File | /api/file/structure/{fileId} | GET | 获取Word文档结构 |
| File | /api/file/generate-doc | POST | 基于模板生成文档 |
| Core | /api/v1/project-templates/bind | POST | 项目绑定模板 |
| Core | /api/v1/project-templates/project/{id} | GET | 获取项目模板 |
| Core | /api/v1/documents/integrate/{projectId} | POST | 执行文档集成 |

### 4. 端到端流程

```bash
# 1. 上传Word模板文件
curl -X POST http://localhost:8081/api/file/upload -F "file=@template.docx" -F "bizType=template"
# 返回 fileId

# 2. 创建模板（fileId自动触发结构解析）
curl -X POST http://localhost:8080/api/v1/template-configs -d '{"templateCode":"...","templateName":"...","fileId":<fileId>,...}'

# 3. 项目绑定模板（创建快照）
curl -X POST http://localhost:8082/api/v1/project-templates/bind -d '{"projectId":<id>,"supTemplateId":<id>}'

# 4. 文档集成生成
curl -X POST http://localhost:8082/api/v1/documents/integrate/<projectId>
```

## 📝 备注

### 验证过程踩坑记录

1. **登录需 RSA 加密**: /api/auth/login 需要 RSA 加密密码 + keyId，流程为 GET /api/auth/public-key → RSA 加密密码 → POST /api/auth/login
2. **poi-tl SpringEL 陷阱**: `useSpringEL()` 对 Map 类型数据不友好，SpEL 用反射查找 getter 方法而非 Map.get()，缺失字段抛异常。必须使用原生引擎。
3. **InternalFileServiceClient 错误处理**: parseGeneratedFileId 不检查响应 code，File 服务返回 500 时 data 为 null，导致误导性的"数据为空"错误。应先检查 code!=200 提取具体错误。
4. **测试 Word 模板生成**: 使用 python-docx 可快速生成带 poi-tl 占位符的测试 .docx 文件
