## 🔴 核心问题（三层叠加）

### 问题1：poi-tl 不支持循环行内单元格合并
- `{{?list}}` 循环为每条数据创建一行，但无法设置垂直合并(CTVMerge)
- **解决方案已确定**: poi-tl 渲染后用 Apache POI API 补做合并

### 问题2：Word 模板标签碎片化 Run
Word/WPS 把 `{{?creditItems}}` 拆成6个碎片 Run + 3个 proofErr 标记：

```xml
<w:r><w:t>{</w:t></w:r>          ← Run1
<w:proofErr type="gramStart"/>
<w:r><w:t>{</w:t></w:r>          ← Run2
<w:r><w:t>?</w:t></w:r>           ← Run3 (rPr有w:hint差异)
<w:proofErr type="spellStart"/>
<w:r><w:t>creditItems</w:t></w:r> ← Run4
<w:proofErr type="spellEnd"/>
<w:proofErr type="gramEnd"/>
<w:r><w:t>}}</w:t></w:r>          ← Run5
```

**解法**: DOM 阶段 `removeSpellGrammarMarkers` + `mergeFragmentedRuns` ✅ 已解决

### 问题3：poi-tl 相邻标签合并 Bug（当前卡点）
模板中 `{{?allReviewItems}}{{categoryName}}` 两个独立标签被 poi-tl 当成**一个标签**：
```
Mismatched start/end tags: No end iterable mark found for start mark {{?allReviewItems}}{{categoryName}} null
```

**已深入分析到 poi-tl 字节码级别**：
- poi-tl 正则 `\{\{(@|=|#|\*|\+|\?|/)?((#)?[\w一-龥]+(\.[\w一-龥]+)*)?\}\}` **能正确匹配两个标签**（Python验证）
- 但 `RunningRunBody` 内部 `refactorRun()` 仍将相邻标签合并
- **无论预拆分还是不拆分，poi-tl 内部都把相邻标签当成一个**

## 🔧 技术约束

- **poi-tl 1.12.2**: 必须使用原生引擎 `Configure.builder().build()`，禁止 SpringEL
- **循环标签必须用 `{{?xxx}}` 不是 `{{#xxx}}`**（AI最常犯的错误）
- poi-tl 的循环标签只支持顶层 key，不支持嵌套路径
- poi-ooxml-full 已引入（支持 CTVMerge/STMerge）
- **XMLBeans DOM 不支持 DOM Level 3**: `getTextContent()`/`setTextContent()` 抛异常
- **DOM 创建的节点不被 XMLBeans 序列化**: `cloneNode()`/`insertBefore()` 创建的 Element 在 `doc.write()` 时丢失
- **DOM 的 `removeChild`/`setNodeValue` 是同步的**: `acceptAllRevisions` 用的这些操作能正确持久化
- **poi-tl 的 refactorRun 会合并同格式 Run**: 这是标签合并的根源
- JDK 必须用 21（`D:/Users/admin/.jdks/openjdk-21.0.5`）
- MySQL: `127.0.0.1:3306/ele_ai_tender` 密码 `123456`

### 碎片化 Run 阶段

| # | 方案 | 结果 | 原因 |
|---|------|------|------|
| 1 | DOM API 拆分合并 Run (cloneNode+setTextContent) | ❌ | XMLBeans 不支持 DOM Level 3 |
| 2 | DOM Level 1 兼容写法 (getFirstChild().setNodeValue) | ❌ | cloneNode 创建的节点不被序列化 |
| 3 | POI 高层 API 拆分（无格式差异） | ❌ | refactorRun 将同格式 Run 合并回来 |
| 4 | POI 高层 API 拆分 + spacing 格式差异 | ❌ | formatStyle 不比较 w:spacing |

### 相邻标签合并阶段

| # | 方案 | 结果 | 原因 |
|---|------|------|------|
| 5 | POI 预拆分 Run + 不同 rPr（w:spacing 差异） | ❌ | refactorRun 忽略 rPr 差异，合并回去 |
| 6 | POI 预拆分 Run + 不同 rsidR 属性 | ❌ | rsidR 不在 rPr 中，refactorRun 不检查 |
| 7 | `Configure.builder().disableRunRefactorize()` | ❌ | poi-tl 1.12.2 没有此方法 |
| 8 | DOM 阶段用 createElementNS 拆分 Run | ❌ | XMLBeans DOM 序列化不可靠 |
| 9 | 零宽空格(U+200B) Run 分隔相邻标签 | ❌ | refactorRun 仍合并，零宽空格被忽略 |
| 10 | 完全去掉预拆分，让 poi-tl 自己处理 | ❌ | 同样错误，poi-tl 自身 refactorRun 有问题 |
| 11 | 修复 si++ 偏移 Bug（改用 offset 变量） | ✅ Bug修复 | 修复了索引跳过问题，但核心合并问题仍在 |

## 📝 当前 WordTemplateEngine 预处理流程

```
preprocessTemplate(templateStream)
  → Step1: DOM阶段
    → XWPFDocument(stream)
    → acceptAllRevisions(bodyNode)        // 清修订标记 ✅
    → removeSpellGrammarMarkers(bodyNode) // 删proofErr ✅
    → mergeFragmentedRuns(bodyNode)       // 合并碎片Run ✅
    → doc.write() → cleaned bytes
  → Step2: 直接传给 poi-tl（已去掉POI阶段预拆分）
    → poi-tl compile + render
    → refactorRun() 把相邻标签合并成一个 ❌
    → 报错 Mismatched start/end tags
```

## 📝 经验沉淀

### poi-tl 标签语法规范

| 标签类型 | 语法 | 数据类型 |
|----------|------|----------|
| 文本 | `{{var}}` | String / TextRenderData |
| **循环** | **`{{?items}}...{{/items}}`** | `List<?>` |
| 图片 | `{{@var}}` | PictureRenderData |
| 包含 | `{{+var}}` | Include |
| 条件 | `{{var}}...{{var}}` | Boolean |

**AI常犯错误**: `{{#items}}`(应`{{?items}}`), `{{image}}`(应`{{@image}}`), `{% for %}`(Jinja2语法)

### poi-tl 1.12.2 GramerSymbol 定义

| 符号名 | 字符 | ASCII |
|--------|------|-------|
| IMAGE | `@` | 64 |
| TEXT | (无) | 0 |
| TEXT_ALIAS | `=` | 61 |
| TABLE | `#` | 35 |
| NUMBERING | `*` | 42 |
| DOCX_TEMPLATE | `+` | 43 |
| **ITERABLE_START** | **`?`** | **63** |
| BLOCK_END | `/` | 47 |

### 关键经验教训
- XMLBeans DOM 的 `removeChild`/`setNodeValue` 能同步到 XMLBeans，但 `cloneNode`/`createElement`/`createTextNode` 不能
- poi-tl 的 `refactorRun` 是编译前的必经步骤，无法通过 Configure 跳过
- Word 的 `<w:proofErr>` 是标签碎片化的主要原因之一，必须在预处理中删除
- poi-tl 正则能正确匹配两个独立标签，但内部处理仍可能合并
