## 问题背景

**项目**：招标文件AI编制工具（tender-document-tool）
**模块**：需求级智能检测（RequirementDetect）+ 业务需求编辑器（RequirementGenerate/WysiwygEditor）

**涉及组件**：
- 后端：`RequirementServiceImpl`、`DetectionResultParser`、`TbDetectionRecordMapper`、`DetectionIssueVO`(ai/core)、`PromptTemplates`
- 前端：`RequirementDetect.vue`、`RequirementGenerate.vue`、`WysiwygEditor.vue`、`detection.ts`
- AI模块：4种检测器（SensitiveWord/Typo/PolicyReview/FormatCheck）

需求智能检测对业务需求内容执行敏感词+错别字两项AI检测，用户可接受/拒绝建议，接受时自动替换原文。

## 已完成工作（已提交 `0e4907d`）

### 问题1：重新检测时旧记录未清理 ✅
- **表现**：点击"重新检测"后旧 `TbDetectionRecord` 仍在数据库，`restoreDetectionState()` 加载全部记录导致 issues 重复和 recordId 错位
- **方案**：`submitDetection()` 前调用 `softDeleteByRequirementId()` 软删除旧记录；前端 `restoreDetectionState()` 按类型 Map 去重只取最新记录

### 问题2：后端 VO 字段缺失 ✅
- **方案**：core模块 `DetectionIssueVO` 补全 `original` + `targeted` 字段；`DetectionResultParser` 补全解析

### 问题3：targeted 字段语义纠正 ✅
- **初始错误理解**：targeted 作为高亮定位文本，suggestion 仍作替换目标
- **正确语义**：`targeted` 是替换原文的内容，替代原来 `suggestion` 在自动替换中的角色
- **方案**：`acceptDetectionIssue()` 替换逻辑改为 `replaceFirst(original, targeted)`；前端"替换建议"优先展示 `targeted`，无则降级 `suggestion`

### 问题4：接受建议时原文不存在无状态反馈 ✅
- **方案**：新增 `handleStatus=3`（未找到），`updateFlag=false` 时设为3；前端四种显式标签：0=未处理/1=已接受(success)/2=已拒绝(info)/3=未找到(warning)

### 问题5：查看原文弹窗优化 ✅
- **方案**：position 作标题（灰色小字），original 作内容（黄色高亮 mark）

## 当前进行中：编辑器内检测高亮

### 需求描述
在业务需求生成页面（RequirementGenerate），如果已有检测结果，在 WysiwygEditor（TipTap）编辑器中对应的 `original` 文本显示高亮，使用户直接看到问题位置。

### 技术方案

**核心机制**：TipTap 基于 ProseMirror，有 `Decoration` API 可以在不修改文档内容的情况下添加视觉高亮。

```
数据流：检测记录 API → original+severity → RequirementGenerate
       → detectionHighlights prop → WysiwygEditor
       → 自定义Extension → ProseMirror DecorationSet → 原文高亮渲染
```

**高亮样式设计**：
| severity | 效果 |
|----------|------|
| HIGH | 红色下划线 + 浅红背景 |
| MEDIUM | 橙色下划线 + 浅橙背景 |
| LOW | 蓝色下划线 + 浅蓝背景 |
| 已处理(1/2/3) | 灰色删除线/不显示 |

**难点**：
1. 内容以 Markdown 存储，ProseMirror 渲染后文本位置变化，需在 ProseMirror 文档树中搜索
2. 同一段文字多次出现时需匹配正确位置（可用 `position` 字段辅助定位）
3. 内容编辑后高亮位置需重新计算（监听 document update 事件重建 DecorationSet）

### 实现步骤（待实施）
1. `WysiwygEditor.vue` 新增 `highlights` prop（传入检测问题列表）
2. 创建 TipTap 自定义 Extension，使用 ProseMirror 的 `Decoration.inline()` 生成装饰
3. Extension 内部：遍历 highlights，在 ProseMirror doc 中搜索 `original` 文本位置，创建 Decoration
4. `RequirementGenerate.vue` 在 `onMounted` 中调 `getDetectionRecords` 获取检测结果，传给 editor
5. 添加高亮样式 CSS

---

## 技术约束

- `TbDetectionRecord` 继承 `BaseEntity`，有 `@TableLogic` 逻辑删除（`is_delete` 字段）
- 软删除用原生 `@Update` SQL 绕过 `@TableLogic`，不更新 `ver/modifyTime`
- WysiwygEditor 使用 TipTap (vue-3)，内容以 Markdown 格式存储
- TipTap 的 `Markdown` extension 负责双向转换，ProseMirror 文档树与 Markdown 源码位置不完全对应
- 编辑器有节流机制（`scheduleFlush` 200ms），高频更新需注意性能

## handleStatus 状态码（完整）

```
0 = 未处理（显示接受/拒绝按钮）
1 = 已接受（success标签，后端已执行 replaceFirst(original, targeted)）
2 = 已拒绝（info标签，仅更新状态）
3 = 未找到（warning标签，原文已不存在，替换未执行）
```

## AI检测结果JSON格式（最新版）

```json
{
  "issues": [
    {
      "position": "问题位置描述",
      "original": "原文内容（查找定位+查看原文弹窗内容）",
      "targeted": "修改内容（直接替换original，替代原suggestion的替换角色）",
      "suggestion": "修改建议（辅助描述，不再用于自动替换）",
      "reason": "问题原因",
      "severity": "HIGH|MEDIUM|LOW",
      "handleStatus": 0,
      "detectionType": "TYPO",
      "policyReference": "（政策审查专用）",
      "ruleViolated": "（格式检测专用）"
    }
  ],
  "score": 85
}
```

## 自动替换逻辑

```
接受建议 → find original in content → replaceFirst(original, targeted)
  ├─ 找到 → handleStatus=1（已接受）
  └─ 未找到 → handleStatus=3（未找到）
```
