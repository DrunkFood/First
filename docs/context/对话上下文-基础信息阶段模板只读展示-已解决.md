# 对话上下文：基础信息阶段模板只读展示

> 生成时间：2026-04-23 | 状态：已解决

---

## 📋 问题背景

**项目**：招标文件AI编制工具（ele-ai-tender）

**涉及模块**：前端 `ele-ai-tender-frontend`，后端 `ele-ai-tender-core`

**相关组件**：
- `PhaseBasicInfo.vue` — 基础信息录入阶段组件
- `ProjectTemplateController.java` — 项目模板管理控制器
- `ProjectTemplateServiceImpl.java` — 项目模板服务实现
- `projectTemplate.ts` — 前端项目模板 API

**当前状态**：基础信息录入阶段完成后（readonly模式），"选择招标文件模板"区域仍展示全部模板卡片，不符合预期。

---

## 🔴 核心问题

**问题表现**：基础信息阶段结束后，回看该阶段时模板选择区域展示所有 `sup_template` 模板，而非只展示项目绑定的那一个模板。

**根源**：`PhaseBasicInfo.vue` 的 `onMounted` 无条件调用 `loadTemplates()` 加载全量模板列表，readonly 模式下也展示全量列表。

---

## 🎯 实现目标

- 编辑模式（基础信息阶段进行中）：展示 `sup_template` 全量模板供选择
- 只读模式（基础信息阶段已结束）：从 `tb_project_template` 查询项目绑定的模板快照，只展示该模板

---

## 🔧 技术约束

- `tb_project_template` 是 `sup_template` 的只读快照，保存模板绑定时的字段副本
- 后端已有 `GET /api/v1/project-templates/project/{projectId}` 接口，前端已有 `projectTemplateApi.getByProject()` 调用
- `TbProjectTemplate` 实体无 `description`/`isDefault`/`status` 字段，需映射为 `TemplateInfo` 类型
- 模板卡片渲染依赖 `TemplateInfo` 类型的 `id`、`templateName`、`content`、`structureDefinition`、`fileId`、`modifyTime`、`createTime` 字段

---

## 🚫 已尝试的方案

### 方案1：前端过滤模板列表（❌ 被否决）

**做法**：在 `displayTemplateList` 计算属性中，readonly 时从 `templateList` 中 `filter` 出 `form.templateId` 匹配的项。

**问题**：
- 仍然依赖 `sup_template` 全量数据，而非项目绑定的快照
- `form.templateId` 在 `bindTemplate()` 后指向 `tb_project_template.id`（快照ID），而非 `sup_template.id`，过滤逻辑会失效
- 不符合用户"通过新接口从 tb_project_template 查询"的要求

---

## ✅ 最终方案

### 设计思路

编辑模式与只读模式使用不同的数据源：

| 模式 | 数据源 | 加载方式 |
|------|--------|----------|
| 编辑 | `sup_template` 全量列表 | `templateApi.getList()` |
| 只读 | `tb_project_template` 项目快照 | `projectTemplateApi.getByProject()` |

### 核心机制

1. 新增 `projectTemplateSnapshot` ref 存储项目模板快照
2. `displayTemplateList` 计算属性：编辑模式返回 `templateList`，只读模式返回 `[projectTemplateSnapshot]`
3. `loadProjectTemplate()` 方法：调用已有接口，将 `TbProjectTemplate` 映射为 `TemplateInfo`
4. `onMounted` 根据 Readonly 属性决定加载哪个数据源

### 关键代码

```typescript
// 项目模板快照（readonly时从tb_project_template查询）
const projectTemplateSnapshot = ref<TemplateInfo | null>(null)

// 展示用模板列表：编辑模式=全量，只读模式=项目绑定模板
const displayTemplateList = computed<TemplateInfo[]>(() => {
  if (!props.readonly) return templateList.value
  return projectTemplateSnapshot.value ? [projectTemplateSnapshot.value] : []
})

// 只读模式下加载项目模板快照
const loadProjectTemplate = async () => {
  try {
    const pt = await projectTemplateApi.getByProject(props.projectId)
    if (pt) {
      projectTemplateSnapshot.value = {
        id: pt.id,
        templateName: pt.templateName,
        projectCategory: pt.projectCategory,
        projectType: pt.projectType,
        fileId: pt.fileId,
        content: pt.content,
        structureDefinition: pt.structureDefinition as any,
        versionNo: pt.versionNo,
        isDefault: 0,
        status: 'PUBLISHED',
        createTime: pt.createTime,
        modifyTime: pt.modifyTime,
      }
    }
  } catch {
    // 查询失败不报错，展示为空
  }
}

// onMounted 按模式加载不同数据源
onMounted(() => {
  loadProject()
  if (props.readonly) {
    loadProjectTemplate()
  } else {
    loadTemplates()
  }
})
```

## 📝 备注

### 关于 sup_template 的 description 与 content 字段区别

| 字段 | 含义 | 用途 |
|------|------|------|
| `description` | 模板描述 | "这个模板是什么"，供管理员在模板列表中快速识别 |
| `content` | 模板用途说明 | "怎么用"，描述适用场景和功能指引 |

`tb_project_template` 快照只复制了 `content`，没有复制 `description`。
