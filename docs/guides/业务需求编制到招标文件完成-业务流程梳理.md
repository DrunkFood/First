## 二、项目状态机

```mermaid
stateDiagram-v2
    [*] --> DRAFT : 创建项目

    DRAFT --> IN_PROGRESS : 开始编制（推进到阶段2）
    DRAFT --> CANCELLED : 取消

    IN_PROGRESS --> PENDING_DETECTION : 提交检测（阶段5）
    IN_PROGRESS --> CANCELLED : 取消

    PENDING_DETECTION --> DETECTING : 自动进入检测
    PENDING_DETECTION --> IN_PROGRESS : 撤回检测
    PENDING_DETECTION --> CANCELLED : 取消

    DETECTING --> DETECTION_PASSED : 全部检测通过
    DETECTING --> DETECTION_FAILED : 检测发现问题
    DETECTING --> DETECTION_SKIPPED : 跳过检测（发警告通知）

    DETECTION_FAILED --> IN_PROGRESS : 返回修改

    DETECTION_PASSED --> PUBLISHED : 发布
    DETECTION_PASSED --> IN_PROGRESS : 返回修改
    DETECTION_SKIPPED --> PUBLISHED : 发布（含警告）
    DETECTION_SKIPPED --> IN_PROGRESS : 返回修改

    PUBLISHED --> ARCHIVED : 归档

    note right of ARCHIVED : 终态，不可变更
    note right of CANCELLED : 终态，不可变更
```

**关键约束**：
- 不允许跳过中间状态
- 每次状态变更记录操作日志
- 终态（ARCHIVED、CANCELLED）不可逆

## 三、第一阶段：业务需求编制

### 3.1 需求状态流转

```mermaid
stateDiagram-v2
    [*] --> IN_PROGRESS : 创建需求（后端默认）

    IN_PROGRESS --> GENERATING : 点击AI生成（前端状态）
    GENERATING --> IN_PROGRESS : 生成失败/AI不可用

    IN_PROGRESS --> COMPLETED : 完成检测通过

    note right of COMPLETED : 可创建项目
    note right of IN_PROGRESS : 后端仅此两种状态
```

> **前后端状态差异**: 后端 `TbRequirement.status` 仅有 `IN_PROGRESS` 和 `COMPLETED` 两种值，无状态机校验。前端 `status-maps.ts` 定义了更丰富的5种状态（DRAFT/GENERATING/PENDING_REVIEW/APPROVED/REJECTED）用于UI展示，但后端不识别 DRAFT/GENERATING/PENDING_REVIEW/APPROVED/REJECTED。需求侧状态通过 `update()` 接口自由设置，与项目侧 `ProjectStateMachine` 不同。

### 3.4 需求匹配 — 三种模式详解

#### 3.4.1 自动匹配（AUTO_MATCH）

```mermaid
flowchart LR
    A["需求信息<br/>projectType + projectCategory"] --> B["调用AI匹配<br/>POST /ai/match/auto<br/>返回Top5历史需求"]
    B --> C["计算匹配度评分"]
    C --> D["按评分降序<br/>取Top5返回"]

    subgraph 评分算法["匹配度评分(0-100分)"]
        S1["项目类型匹配: 40分"]
        S2["项目类别匹配: 20分"]
        S3["预算范围匹配: 10分"]
        S4["关键词匹配: 20分<br/>项目名称占满20分<br/>描述占一半10分"]
    end

    C --> 评分算法

    style 评分算法 fill:#1a3a5c,stroke:#4a9eff,color:#e0e0e0
```

**API端点**: `POST /api/v1/ai/match/auto`

**匹配结果写入**: `match_mode=AUTO_MATCH` + `matched_file_id=选中需求ID` + `matched_similarity=评分`

#### 3.4.2 手动选择（MANUAL_SELECT）

- **获取匹配文件列表**: `GET /api/v1/requirements/match-files` — 按项目类型和关键词过滤，返回匹配度百分比
- **确认匹配**: `POST /api/v1/requirements/{id}/match` — 写入 `matchMode` + `matchedFileId`
- 默认匹配模式为 `MANUAL_SELECT`
- 用户从列表中手动选择一条

#### 3.4.3 上传文件（UPLOAD）

- 调用文件服务 `POST /file/upload` 上传本地文件
- 格式限制：doc/docx/pdf，大小不超过50MB
- 上传成功后 `uploaded_file_id` 写入需求记录

### 3.5 AI生成需求内容 — 详细流程

```mermaid
sequenceDiagram
    participant 前端 as 前端(RequirementGenerate.vue)
    participant Core as Core模块(8082)
    participant DB as ai_task表
    participant AI as AI模块(8083)
    participant Model as 大模型API

    前端->>Core: POST /requirements/{id}/generate
    Core->>DB: INSERT ai_task<br/>type=REQUIREMENT_GENERATE<br/>status=PENDING<br/>bizType=REQUIREMENT<br/>params={requirementId, name, type, budget}
    DB-->>Core: taskId
    Core-->>前端: 返回 AiTask

    Note over 前端: 前端通过轮询等待结果

    loop 每5秒轮询PENDING任务
        AI->>DB: SELECT WHERE status=PENDING (最多10条)<br/>CAS抢占(status→PROCESSING)
        AI->>AI: RequirementGenerator.generate(task)
        AI->>AI: PromptBuilder.buildRequirementGenerate()<br/>构建System Prompt + User Prompt
        AI->>Model: ModelRouter.route(REQUIREMENT_GENERATE)<br/>→ GENERATION场景模型
        Model-->>AI: AI输出(Markdown)
        AI->>AI: resultParser.extractMarkdown(output)
        AI->>DB: UPDATE status=COMPLETED<br/>result={"content": "..."}<br/>resultSynced=0
    end

    Note over Core: 结果同步调度器(10s轮询)
    loop 每10秒同步已完成任务
        Core->>DB: SELECT WHERE status=COMPLETED AND resultSynced=0
        Core->>DB: UPDATE tb_requirement.content=结果内容<br/>resultSynced=1
    end

    前端->>Core: GET /ai-tasks/{id}（3秒轮询）
    Core-->>前端: COMPLETED + content
    前端->>前端: 渲染Markdown到编辑器
```

**System Prompt 要点**（来自 `SystemPromptTemplates.java` / `UserPromptTemplates.java`，三步式编排：大纲→分章并行→拼接→审查修订，通过 `ai_task.result` 渐进式推送 `contentStage`，全文硬约束 ≤5000 字）：
- 输出 Markdown 格式的需求文档
- 包含技术要求、商务要求、服务要求等章节
- 需求条款应具体、可量化、可验证
- 避免歧视性、限制性、排他性表述
- 符合招投标法规要求

**User Prompt 参数**: `projectName`, `projectType`, `projectCategory`, `budget`, `description`, `referenceContent`

**需求检测 vs 项目检测对比**：

**衔接路径**：
1. 从需求列表点击"创建项目" → 自动关联需求（`requirementId`写入项目）
2. 从项目列表直接创建 → 无关联需求
3. 进入需求阶段时，有关联需求→复制内容到 `project.requirementContent`；无关联→触发AI需求生成
4. 之后项目和需求再无关联，后续阶段均从 `project.requirementContent` 读取

### 3.10 降级策略

```mermaid
flowchart TD
    A["AI任务提交"] --> B{AI模块是否拉取}
    B -->|是| C["正常执行"]
    B -->|否| D["AiTaskTimeoutChecker<br/>60s扫描超时任务<br/>标记 AI_UNAVAILABLE"]
    D --> E{用户操作}
    E -->|重试| F["重新提交任务"]
    E -->|跳过| G["SKIPPED<br/>降级手动输入"]
    C --> H{执行结果}
    H -->|成功| I["COMPLETED<br/>resultSynced=0"]
    I --> I2["AiTaskResultSyncScheduler<br/>10s同步结果到业务表<br/>resultSynced=1"]
    H -->|失败| J["FAILED"]
    J --> K{重试次数<maxRetry?}
```

## 六、AI任务机制详解

### 6.1 异步任务队列流程

```mermaid
sequenceDiagram
    participant 前端
    participant Core模块
    participant DB as ai_task表
    participant AI模块
    participant 大模型

    前端->>Core模块: POST /requirements/{id}/generate
    Core模块->>DB: INSERT ai_task (status=PENDING, bizType=REQUIREMENT)
    Core模块-->>前端: 返回 taskId

    loop 每3秒轮询
        前端->>Core模块: GET /ai-tasks/{id}
        Core模块->>DB: SELECT status
        DB-->>Core模块: 任务状态
        Core模块-->>前端: 返回状态
    end

    loop 每5秒轮询（批量10条）
        AI模块->>DB: SELECT PENDING任务 (CAS抢占)
        DB-->>AI模块: 获得任务
        AI模块->>DB: UPDATE status=PROCESSING
        AI模块->>大模型: ModelRouter.route(taskType) → 按使用场景选择模型
        大模型-->>AI模块: 返回结果
        AI模块->>DB: UPDATE status=COMPLETED, result=内容, resultSynced=0
    end

    Note over Core模块: AiTaskResultSyncScheduler 每10秒同步
    loop 每10秒扫描
        Core模块->>DB: SELECT WHERE resultSynced=0
        Core模块->>DB: 更新业务表内容, resultSynced=1
    end

    前端->>Core模块: GET /ai-tasks/{id}
    Core模块-->>前端: COMPLETED + result
```

### 6.2 八种AI任务类型

| 任务类型 | 场景 | 路由场景 | 通信方式 |
|---------|------|---------|---------|
| REQUIREMENT_GENERATE | 需求生成 | GENERATION | 异步队列 |
| PROJECT_REQUIREMENT_GENERATE | 项目需求生成 | GENERATION | 异步队列 |
| REVIEW_ITEM_GENERATE | 评审项生成 | GENERATION | 异步队列 |
| DETECTION_SENSITIVE_WORD | 敏感词检测 | DETECTION | 异步队列 |
| DETECTION_TYPO | 错别字检测 | DETECTION | 异步队列 |
| DETECTION_POLICY_REVIEW | 政策审查 | DETECTION | 异步队列 |
| DETECTION_FORMAT_CHECK | 格式检测 | DETECTION | 异步队列 |
| TEXT_OPTIMIZE | 文本优化 | OPTIMIZATION | 异步队列 |

### 6.3 任务状态流转

```
PENDING → PROCESSING → COMPLETED (resultSynced=0 → 同步后resultSynced=1)
                     → FAILED（可重试，retryCount < maxRetry）
                     → AI_UNAVAILABLE（AiTaskTimeoutChecker 60s扫描超时任务）
                     → SKIPPED（用户主动跳过）
```

- Core → File: 直接HTTP调用文件上传/下载
- Core → Support: 直接HTTP调用认证/权限校验
- AI → File: 直接HTTP调用知识库文件管理
- AI → Support: 查询模型配置和路由规则
- 前端 → AI: SSE直连（AI对话/文本优化），其他走Core转发
- Core结果同步: `AiTaskResultSyncScheduler`(10s) 将AI任务结果同步到业务表
- Core超时检查: `AiTaskTimeoutChecker`(60s) 标记超时未拉取的任务
