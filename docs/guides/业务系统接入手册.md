## 1. 目的

本文档说明业务系统如何接入 `ele-tender-interaction-spring-boot-starter`，以及当前仓库代码对应的固定接口、SPI、配置项和调用边界。

适用范围：

- 获取 external token
- 获取当前外部用户身份
- 构造招标文件编制页入口
- 查询文件信息和下载文件
- 接收招标文件、数据包、投标文件预存结果、解密结果等回调

## 2. 兼容性

- JDK：`8`
- Spring Boot：建议 `2.7.x`
- Web：必须是 Spring MVC Web 应用
- Servlet API：运行时需提供 `javax.servlet`

不建议直接接入的场景：

- 非 Spring Boot 工程
- 非 Web 工程
- 仅有 WebFlux、没有 Spring MVC

## 3. 依赖

```xml
<dependency>
    <groupId>com.jy.eletender</groupId>
    <artifactId>ele-tender-interaction-spring-boot-starter</artifactId>
    <version>1.1.3-SNAPSHOT</version>
</dependency>
```

## 4. 模块组成

- `ele-tender-common-interaction`
  协议 DTO、SPI、常量、统一交互返回
- `ele-tender-interaction-core`
  出站 client、签名器、入口 URL 构造器
- `ele-tender-interaction-autoconfigure`
  自动装配、固定 controller、签名校验
- `ele-tender-interaction-spring-boot-starter`
  对业务系统暴露的 starter 聚合产物

> **注意**：1.1.3 版本起，原 `FileInfoClient` 和 `FileDownloadClient` 已合并为 `FileClient`，同时新增文件上传能力。

## 5. 最小配置

```yaml
ele-tender:
  interaction:
    enabled: true
    api-base-url: http://support-host:8080
    page-base-url: http://page-host:8080
    file-base-url: http://file-host:8081
    crypto-base-url: http://crypto-host:8083
    app-key: your-app-key
    app-secret: your-app-secret
    token-path: /api/external/token
    user-info-path: /api/external/userinfo
    tender-document-page-path: /tender-document/compose
    file-info-path: /api/file/info/{fileId}
    file-download-path: /api/file/download/{fileId}
    file-upload-path: /api/file/upload
    bid-document-push-path: /api/crypto/bid-document/push
    bid-decrypt-submit-path: /api/crypto/bid-decrypt/submit
    bid-decrypt-status-path: /api/crypto/bid-decrypt/status/{recordId}
    envelope-join-path: /api/crypto/envelope/join
    connect-timeout: 5s
    read-timeout: 20s
```

说明：

- `api-base-url` 用于 support 侧 token/userinfo 等接口
- `page-base-url` 用于拼接编制页访问地址
- `file-base-url` 用于文件服务
- `crypto-base-url` 用于加解密服务

## 6. 当前固定接口

统一前缀：`/api/eleTender/interaction`

- `GET /identity/current`
- `POST /projects/basic-info`
- `POST /bid-record-schemes/query`
- `POST /ca-keys/query`
- `POST /callbacks/tender-pdf`
- `POST /callbacks/tender-package`
- `POST /callbacks/bid-document-result`
- `POST /callbacks/bid-decrypt-result`

业务系统不需要自己手写这些 controller，只需要实现对应 SPI。

## 7. 必须实现的 SPI

- `InteractionIdentityService`
- `InteractionProjectInfoService`
- `InteractionBidRecordSchemeService`
- `InteractionCaKeysInfoService`
- `InteractionTenderPdfReceiveService`
- `InteractionTenderPackageReceiveService`
- `InteractionBidDocumentResultReceiveService`
- `InteractionBidDecryptResultReceiveService`

可选：

- `InteractionEventLogger`

## 8. 出站能力

通过 `EleTenderInteractionClient` 可直接调用：

- `getExternalToken`
- `getCurrentExternalUser`
- `getFileInfo`
- `downloadFile`
- `uploadFile`（支持 byte[] 或本地文件路径两种方式）
- `pushBidDocument`
- `submitDecrypt`
- `queryDecryptStatus`
- `joinEnvelope`
- `buildTenderDocumentEntryUrl`

## 9. 模型边界要求

- 协议 DTO 单源放在 `ele-tender-common-interaction`
- controller/facade 边界通过 mapper 做显式转换
- service 层不直接透传协议 DTO
- 协议 DTO 默认不承载 `jakarta/javax.validation` 注解
- 新增或变更协议字段时，必须同步更新 mapper 与测试

## 10. 安全要求

- support 侧外部接口签名使用 `HMAC-SHA256`
- 交互链路统一透传 `X-Trace-Id`
- `appSecret` 必须由环境变量或配置中心注入，禁止写死代码
- 生产环境应使用 HTTPS

## 11. 推荐联调顺序

1. 配置 `appKey`、`appSecret`、各服务 base URL
2. 验证 `POST /api/external/token`
3. 验证 `GET /api/external/userinfo`
4. 验证固定 SPI 接口
5. 验证文件查询/下载/上传
6. 验证编制入口 URL 构造
7. 如接入 crypto，再验证预存、解密和回调

## 12. 解密服务接入

> 以下内容原在 `业务系统接入解密服务指南.md`，现合并至此。

### 12.1 概述

`ele-tender-crypto` 提供四类能力：

1. 投标文件预存
2. 解密请求提交
3. 解密状态查询
4. 密钥信封拼接（envelope/join）

所有接口统一使用 external JWT 认证；回调路径由 starter 自动注册。

### 12.2 需要实现的 SPI

#### 文件预存结果回调

```java
@Component
public class BidDocumentResultHandler implements InteractionBidDocumentResultReceiveService {
    @Override
    public void onBidDocumentResult(BidDocumentResultCallbackRequest request) {
        // 根据 fileId 和 uploadResult 更新本地投标文件状态
    }
}
```

#### 解密结果回调

```java
@Component
public class BidDecryptResultHandler implements InteractionBidDecryptResultReceiveService {
    @Override
    public void onDecryptResult(BidDecryptResultCallbackRequest request) {
        // 根据 bidRecordId、status、bidRecordData、errorMessage 处理结果
    }
}
```

starter 自动注册以下回调端点：

- `POST /api/eleTender/interaction/callbacks/bid-document-result`
- `POST /api/eleTender/interaction/callbacks/bid-decrypt-result`

### 12.3 获取 external JWT

```http
POST /api/external/token
```

请求头：`X-App-Key`、`X-Timestamp`、`X-Signature`

请求体包含：`userId`、`userName`、`enterpriseId`、`enterpriseName`、`enterpriseCode`

建议：
- 文件预存阶段使用系统服务账号
- 开标解密阶段使用真实招标人身份

### 12.4 投标文件预存

> **提示**：从 1.1.3 起，可直接使用 `client.uploadFile(filePath, "BID_DOCUMENT")` 上传投标文件到文件服务，无需业务系统自行对接文件服务上传接口。

```java
// 上传投标文件
InteractionFileUploadResponse uploadResp = client.uploadFile(
        Paths.get("/path/to/bid-file.HzctTbs"), "BID_DOCUMENT");

// 推送预存
BidDocumentPushRequest req = new BidDocumentPushRequest();
req.setFileId(1001L);
req.setFileSha256("abc123def456...");

BidDocumentPushResponse resp = client.pushBidDocument(token, req);
```

crypto 从文件服务下载原始加密文件，校验 SHA256，本地落盘并回调预存结果。

### 12.5 提交解密请求

```java
BidDecryptSubmitRequest req = new BidDecryptSubmitRequest();
req.setProjectId("P001");
req.setTenderId("T001");
req.setBidRecordId("BR001");
req.setFileSha256("abc123def456...");
req.setBidderPwdStr("plain-password-from-client");

BidDecryptSubmitResponse resp = client.submitDecrypt(token, req);
String recordId = resp.getRecordId();
```

### 12.6 查询解密状态

```java
BidDecryptStatusResponse status = client.queryDecryptStatus(token, recordId);
```

### 12.7 密钥信封拼接（envelope/join）

开标系统在通过 CA 私钥解密 `hashKeyList` 中各层的 `hashKeyE` 后，调用此接口还原完整的 `bidderPwdStr`。

```java
EnvelopeJoinRequest req = new EnvelopeJoinRequest();
req.setHashKeyList(hashKeyItems); // 含 caId, hashKeyE, hashKeyD, order

EnvelopeJoinResponse resp = client.joinEnvelope(token, req);
String bidderPwdStr = resp.getBidderPwdStr(); // base64 编码的 32 字节密钥
```

处理逻辑：
- 按 `order` 去重排序，每组取有 `hashKeyD` 的记录
- base64 解码各段，按 order 升序拼接
- 校验总长度 == 32 字节
- 返回 base64 编码的 `bidderPwdStr`

### 12.8 接入注意事项

- `fileSha256` 必须和实际文件内容一致
- crypto 要求文件已先上传到文件服务
- 原始口令不会落库，只在 Redis 短期缓存
- 回调签名与 support 外部接口签名算法保持一致
- 业务系统应按幂等方式处理回调
