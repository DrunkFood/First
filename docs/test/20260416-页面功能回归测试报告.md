## 发现的Bug及修复情况

### Bug #1: 登录过期弹窗重复弹出（已修复）

**严重程度**: 高  
**现象**: 当token过期时，多个API请求同时返回401，每个请求都会弹出一个"登录状态已过期"确认框，导致出现4-5个弹窗叠在一起  
**根因**: `request.ts` 的401响应拦截器没有做去重处理，每次收到401都直接调用 `ElMessageBox.confirm`  
**修复**: 在 `request.ts` 中增加 `isShowing401Dialog` 标志位，确保同时只有一个401弹窗，用 `.finally()` 重置标志  
**文件**: `ele-ai-tender-frontend/src/utils/request.ts`

### Bug #2: 政策文件上传缺少bizType参数（已修复）

**严重程度**: 高  
**现象**: 政策文件上传始终失败，返回 ERR_CONNECTION_RESET  
**根因**: 文件上传URL `/file-api/file/upload` 缺少后端必需的 `bizType` 查询参数  
**修复**: 将上传URL改为 `/file-api/file/upload?bizType=policy_file`  
**文件**: `ele-ai-tender-frontend/src/views/policy/PolicyFileList.vue`

### Bug #3: Vite代理文件上传超时（已修复）

**严重程度**: 中  
**现象**: 较大文件(>1MB)通过Vite代理上传时连接中断 (ERR_CONNECTION_ABORTED)  
**根因**: Vite proxy默认timeout较短，大文件上传来不及完成  
**修复**: 给 `/file-api` 代理添加 `timeout: 60000` (60秒)  
**文件**: `ele-ai-tender-frontend/vite.config.ts`

### Bug #4: 文件服务NoClassDefFoundError（需重启修复）

**严重程度**: 高（后端）  
**现象**: 文件上传API返回 `NoClassDefFoundError: SecurityContextHolder`  
**根因**: common模块变更后未重新install到本地仓库，文件服务使用了旧版common jar  
**修复**: 用JDK 21重新 `mvn install -pl ele-ai-tender-common -am`，然后 `mvn clean compile -pl ele-ai-tender-file -am`，重启文件服务  
**状态**: 已验证修复（curl上传成功）

### Bug #5: 文件服务上传目录不存在（Windows环境）

**严重程度**: 中（后端/环境配置）  
**现象**: 文件上传返回5002，后端日志 `FileNotFoundException: 系统找不到指定的路径`  
**根因**: 默认basePath `/data/ele-ai-tender/files` 是Linux路径，Windows上被解析为Tomcat临时目录的相对路径  
**修复**: 创建本地覆盖配置 `~/.ele-ai-tender/ele-ai-tender-file-local.yml` 设置 `file-storage.base-path: D:/data/ele-ai-tender/files`，或通过环境变量 `FILE_STORAGE_BASE_PATH` 设置  
**状态**: 已验证修复（curl上传成功）

### Bug #6: 文件上传代理指向错误服务（已修复）

**严重程度**: 高
**现象**: 政策文件上传看似成功（el-upload显示绿色勾），但点击"确定"后创建政策文件记录的请求从未发出，对话框停留在原位
**根因**:
1. `.env` 和 `.env.development` 中 `VITE_FILE_API_URL=http://localhost:8083` 指向了AI服务（8083），而非文件服务（8081）
2. `/file-api` Vite代理没有rewrite规则，请求 `/file-api/file/upload` 无法映射到后端 `/api/file/upload`
AI服务收到请求后返回 HTTP 200 但业务码500（`"No static resource file-api/file/upload"`），el-upload只看HTTP状态码误判为成功，而 `handleUploadSuccess` 检查 `response.code === 200` 失败，fileId始终为0
**修复**:
1. 修正 `.env` 和 `.env.development`：`VITE_FILE_API_URL=http://localhost:8081`
2. 在 `vite.config.ts` 的 `/file-api` 代理添加 `rewrite: (path) => path.replace(/^\/file-api/, '/api')`
**文件**: `ele-ai-tender-frontend/.env`, `ele-ai-tender-frontend/.env.development`, `ele-ai-tender-frontend/vite.config.ts`

### Bug #7: 政策文件上传文件名为空+适用类别显示原始枚举值（已修复）

**严重程度**: 中
**现象**: 政策文件上传后，列表中"文件名"列为空，"适用类别"列显示 `LIMITED_BELOW` 而非"限额以下"
**根因**:
1. 文件名为空：el-upload的 `:file-list` 是单向绑定，内部fileList变更不反映到ref，导致提交时 `fileList.value[0]?.name` 为undefined
2. 适用类别显示枚举值：表格列直接用 `prop="applicableCategory"` 渲染，而后端存储的是枚举 `LIMITED_BELOW`
**修复**:
1. 将 `:file-list="fileList"` 改为 `v-model:file-list="fileList"` 实现双向绑定
2. 在 `handleUploadSuccess` 中保存 `fileName`（从后端 `FileUploadResponse.fileName` 获取）
3. 给"适用类别"列添加template，用 `applicableCategoryMap` 映射中文显示
4. 详情对话框中的"适用类别"也做同样映射
**文件**: `ele-ai-tender-frontend/src/views/policy/PolicyFileList.vue`

### Bug #8: 政策文件删除按钮不显示+来源显示不准确（已修复）

**严重程度**: 中
**现象**: 用户上传的政策文件列表中没有"删除"按钮，"来源"列统一显示"用户"
**根因**: 后端分页接口 `getPage` 返回 `AiPolicyFile` 实体，不包含 `source` 字段（source是计算字段，仅 `/all` 接口的 `PolicyFileVO` 中有）。前端 `row.source === 'USER'` 始终为false，删除按钮永远不显示
**修复**:
1. 将删除按钮条件从 `row.source === 'USER'` 改为 `row.source !== 'SYSTEM'`，当source为undefined（分页列表用户文件）时也显示删除按钮
2. "来源"列显示文案从"用户"改为"用户上传"，更清晰
**文件**: `ele-ai-tender-frontend/src/views/policy/PolicyFileList.vue`
