## 三、BUG清单

### BUG-001: 登录失败无错误提示 (致命)

| 项目 | 内容 |
|------|------|
| 用例ID | T-LOGIN-003 |
| 等级 | 致命 |
| 现象 | 输入错误密码登录时，后端返回"用户名或密码错误"，但页面上无任何错误提示信息 |
| 影响 | 用户无法知道登录失败原因 |
| 复现步骤 | 1. 输入正确用户名+错误密码 → 2. 点击登录 → 3. 页面停留在登录页但无提示 |
| 根因分析 | 前端Login.vue捕获了错误(console可见)但未调用ElMessage.error显示给用户 |
| 建议修复 | 在handlePasswordLogin的catch块中添加ElMessage.error提示 |

### BUG-002: AI需求生成卡住，内容始终为空 (致命)

| 项目 | 内容 |
|------|------|
| 用例ID | T-REQ-GEN-001 |
| 等级 | 致命 |
| 现象 | 点击"AI生成"后进度条卡在60%/91%，需求content始终为空，AI任务latest接口返回null |
| 影响 | AI生成核心功能完全不可用，阻塞后续所有流程 |
| 复现步骤 | 1. 创建需求 → 2. 进入AI生成页 → 3. 点击"AI生成" → 4. 进度卡住不动 |
| 根因分析 | 可能原因：(1)AI任务已完成但结果未回写；(2)AI任务静默失败；(3)SSE连接断开但前端未检测到；(4)AI模型配置/路由问题 |
| 建议修复 | 检查AiTaskProcessor执行日志、ai_task表任务状态、ai_response_log表内容 |

### BUG-003: 项目在非检测阶段可提交检测 (严重)

| 项目 | 内容 |
|------|------|
| 用例ID | T-PROJ-DET-001 |
| 等级 | 严重 |
| 现象 | 项目在阶段2(需求生成)时，POST /detection/submit/{projectId}仍返回200，项目状态变为DETECTING |
| 影响 | 绕过阶段流程控制，项目可能在需求内容为空时进入检测，产生无意义结果 |
| 复现步骤 | 1. 创建项目 → 2. 推进到阶段2 → 3. 调用detection/submit → 4. 状态变为DETECTING |
| 根因分析 | DetectionController.submit()未校验项目当前阶段是否为DETECTION(5) |
| 建议修复 | 在submit方法中添加阶段校验：`if (project.getCurrentPhase() < 5) throw new BusinessException("项目尚未进入检测阶段")` |

### BUG-004: 文档自动匹配API请求体格式错误 (严重)

| 项目 | 内容 |
|------|------|
| 用例ID | T-MATCH-001 |
| 等级 | 严重 |
| 现象 | POST /ai/v1/match/auto 返回400"请求体格式错误，请检查JSON结构" |
| 影响 | 自动匹配功能不可用 |
| 复现步骤 | 调用API传递JSON body |
| 根因分析 | 请求体字段名与后端DTO不匹配，需查看DocumentMatchController的请求体定义 |
| 建议修复 | 对齐前端API调用与后端DTO字段名 |

### BUG-005: 默认模板查询返回null (一般)

| 项目 | 内容 |
|------|------|

## 六、测试结论与建议

### 6.1 测试结论

1. **基础功能框架可用**：登录/登出、项目CRUD、需求CRUD、阶段推进、状态流转校验等基础功能正常
