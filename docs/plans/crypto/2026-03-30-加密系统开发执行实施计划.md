# 加密系统开发执行实施计划

> 日期：2026-03-30  
> 需求来源：`docs/projects/2026-03-30-加密系统开发执行需求整理.md`

## 1. 执行目标

- 按阶段完成加密系统全链路开发。
- 每阶段执行固定闭环：`TDD Red -> Green -> 阶段全测 -> 需求对照 -> 不通过则修复复测`。
- 阶段之间通过关口命令串联，保证可回归、可追踪。

## 2. 阶段计划

### 阶段 1：文件服务放开 `.HzctTbs`

- 修改 file 服务 `allowed-types` 默认值。
- 同步修正相关单测断言与错误文案预期。
- 关口：`mvn -pl ele-tender-file -am clean test`

### 阶段 2：external token 多会话兼容

- external token 增加 `jti`。
- Redis key 升级为 `external:token:{appKey}:{userId}:{jti}`。
- 校验逻辑兼容旧 token（无 `jti`）。
- internal token 行为保持不变。
- 关口：
  - `mvn -pl ele-tender-common -am clean test`
  - `mvn -pl ele-tender-support -am clean test`
  - `mvn -pl ele-tender-tender-document -am clean test`

### 阶段 3：common crypto 领域模型

- 新增 `bdc_bid_document`、`bdc_decrypt_artifact`、`bdc_decrypt_request` 对应实体与 mapper。
- 增加 crypto 相关枚举与 `ResponseCode(7001-7013)`。
- 落地“仅指纹入库，不存原始密码”。
- 关口：`mvn -pl ele-tender-common -am clean test`

### 阶段 4：common-interaction 协议扩展

- 增加 bid-document/decrypt 的 DTO 与 callback DTO。
- 增加接收回调 SPI。
- 扩展 `InteractionApiPaths` 与 `InteractionValidationUtils`。
- 关口：`mvn -pl ele-tender-common-interaction -am clean test`

### 阶段 5：interaction starter 扩展

- core 新增 `BidDocumentPushClient`、`BidDecryptClient`。
- `EleTenderInteractionClient` 暴露 crypto 能力。
- autoconfigure 注册 crypto callback controller 与 clients。
- 关口：`cd ele-tender-system/ele-tender-interaction && mvn clean test`

### 阶段 6：新增 `ele-tender-crypto` 模块

- 新增模块与启动/配置/异常/鉴权/mapper/service/controller/consumer/scheduler 结构。
- 对外开放：
  - `POST /api/crypto/bid-document/push`
  - `POST /api/crypto/bid-decrypt/submit`
  - `GET /api/crypto/bid-decrypt/status/{recordId}`
- 主链路：预存文件 -> 创建请求/工件 -> stream -> 解密执行 -> 回调 -> 状态更新。
- JNI 先用 stub。
- 关口：`mvn -pl ele-tender-crypto -am clean test`

### 阶段 7：support 管理能力

- 增加 request 分页、artifact 明细、失败请求重试接口。
- 复用访问日志接口按 `serviceName=ele-tender-crypto` 检索。
- 接口全部 internal token + 权限控制。
- 关口：`mvn -pl ele-tender-support -am clean test`

### 阶段 8：前端代理

- `vite.config.ts` 新增 `/crypto-api` 代理。
- 关口：`cd ele-tender-support-frontend && npm run build`

### 阶段 9：版本统一与发布准备

- `ele-tender-system` 与 interaction 相关模块版本统一为 `2.0.0`。
- 与功能改动分离提交。
- 关口：`cd ele-tender-system && mvn clean compile`

## 3. 最终验收

- 全仓编译通过。
- external token 多会话并发可用。
- crypto push/submit/status/callback 端到端通过。
- 去重、超时恢复、support 管理查询和重试可用。
