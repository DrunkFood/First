# 招标文件AI编制系统 - 推荐架构改造方案

## 二、模块复用评估

### 2.1 高度复用（直接可用，无需改造）

| 模块 | 复用内容 | 应用点 |
|------|---------|--------|
| **ele-tender-common** | JWT认证、BCrypt密码、HMAC签名、统一响应Result、异常体系 | 用户登录、权限验证、API响应 |
| **ele-tender-support** | 用户管理、角色管理、菜单权限、操作日志 | 管理端权限体系、审计日志 |
| **ele-tender-file** | 文件上传/下载/秒传、SHA256校验 | 模板上传、招标文件存储、知识库文件管理 |
| **前端骨架** | Vue3+TS+Pinia+Element Plus项目结构 | AI编制系统前端基础 |

### 2.2 中度复用（需适配改造）

| 模块 | 复用内容 | 改造点 | AI系统应用 |
|------|---------|--------|-----------|
| **ele-tender-tender-document** | 编制流程状态机、步骤管理、规则树结构 | 将6步流程简化为AI场景的3-4步 | 业务需求编制→AI生成→智能检测→导出 |
| | 招标文件JSON组装逻辑 | 增加AI生成内容字段 | 模板+AI填充→JSON→Word |
| | 评审规则管理(td_tender_rule_*) | 支持三级嵌套表格 | 评审项AI生成和编辑 |
| | 版本快照机制 | 复用 | AI生成版本历史 |
| **ele-tender-common-interaction** | 外部系统接入协议 | 新增AI相关DTO | 后续对接第三方招标平台 |

### 2.3 低度复用（参考设计，重新实现）

| 模块 | 参考内容 | AI系统新实现 |
|------|---------|-------------|
| **ele-tender-crypto** | AES加密框架 | 招标文件加密改用AI系统专用密钥 |
| **交互层SPI** | 回调机制 | 新增AI生成回调、知识库查询接口 |
| **前端页面** | 管理页面布局 | 新增AI编辑器、模板选择器、检测面板 |

### 2.4 不复用（AI系统独有）

| 新功能 | 技术选型建议 |
|--------|------------|
| **知识库模块** | 向量数据库(Milvus/Chroma) + 文档解析 + 检索服务 |
| **大模型调用** | OpenAI兼容API封装 + DeepSeek适配 + 私有模型接口 |
| **AI助手(文本优化)** | 流式响应 + 选区交互 + 实时建议 |
| **Markdown模板引擎** | 模板管理 + 变量替换 + Markdown→Word转换 |
| **智能检测** | 对接外部审查能力(非自研) + 问题清单反馈 |
| **模板分类管理** | 多类别适配(产权交易/政府采购) + 差异化模板 |

## 三、核心复用清单

### 立即可用（0改造成本）
1. `ele-tender-common` — 工具类、安全框架
2. `ele-tender-support` — 用户权限体系
3. `ele-tender-file` — 文件存储
4. 前端基础框架 — 路由、请求封装、Pinia

### 需适配（中等工作量）
1. `ele-tender-tender-document` — 编制流程简化、JSON结构扩展
2. 交互协议 — 新增AI相关DTO和接口路径

### 全新开发
1. 知识库模块（向量检索 + 文档管理）
2. AI编排服务（提示词工程 + 模型调用 + 流式响应）
3. 模板管理系统（Markdown模板 + 变量引擎）
4. 智能检测对接（外部审查能力集成）

## 四、架构演进建议

### 4.1 第一阶段：基础框架搭建
- 复用现有认证、文件、权限体系
- 基于前端骨架扩展AI编制页面
- 搭建AI服务模块基础结构

### 4.2 第二阶段：核心能力开发
- 开发知识库模块（文档上传、向量化、检索）
- 实现大模型调用封装（DeepSeek等公有模型）
- 开发Markdown模板引擎

### 4.3 第三阶段：智能功能集成
- AI助手（文本选区优化、实时建议）
- 智能检测对接（外部审查能力）
- 评审项AI生成和三级嵌套表格

### 4.4 第四阶段：对接和优化
- 对接第三方招标平台（复用交互协议）
- 性能优化、格式美化
- 权限体系完善（用户端/管理端分离）

## 五、技术债务和注意事项

### 5.1 现有架构依赖
- JDK 21 + Spring Boot 3.2.2
- MyBatis-Plus 3.5.5
- MySQL 8.4.0 + Redis (db=5)
- 文件存储: /data/ele-tender/files

### 5.2 新增技术栈
- 向量数据库（Milvus/Chroma）
- 大模型SDK（OpenAI兼容、DeepSeek）
- Markdown处理库（flexmark-java等）
- Word生成库（poi-tl等）

### 5.3 安全考虑
- AI生成内容审核机制
- 大模型API密钥管理
- 知识库文档权限控制
- 用户数据隔离

## 六、总结

现有架构约 **60% 可直接复用**（认证、文件、权限、前端骨架），**20% 需适配改造**（编制流程、交互协议），**20% 需全新开发**（AI核心能力）。建议基于现有模块快速搭建基础框架，重点投入AI编排和知识库的开发。
