# 2026-03-19 重新编制功能修复计划

## 目标

恢复"重新编制"能力：entry 按 versionNo 取最新编制单，新增 recompile 端点原地重置 COMPLETED → DRAFT。

## 实施步骤

### 1. 新增错误码

- `TenderDocumentErrorCode` 新增 `RECOMPILE_NOT_ALLOWED(6021, "当前编制单状态不允许重新编制")`

### 2. 新增配置项

- `application.yml` 新增 `tender-document.generation-timeout-seconds`，默认 1800 秒

### 3. 修改 entry 逻辑

- `TenderDocumentServiceImpl.enter()` 改为单次查询 `findLatestDocument`（versionNo DESC，不区分状态）
- 删除 `findDraft` 方法
- DRAFT → 刷新 sync 返回；COMPLETED → 原样返回
- GENERATING 超时 → 重置为 DRAFT + 标记 PROCESSING 生成记录为 FAIL；未超时 → 原样返回
- 新增依赖：`TenderDocumentFileMapper`、`ITenderDocumentGenerationRecordService`、`generationTimeoutSeconds`

### 4. 新增 recompile 方法

- `ITenderDocumentService` 新增 `recompile(Long, TenderDocumentUserContext)` 签名
- `TenderDocumentServiceImpl.recompile()` 实现：
  - 校验 COMPLETED 状态
  - versionNo + 1，status → DRAFT
  - GENERATE_PACKAGE 步骤 → IN_PROGRESS
  - 失效 FINAL_PACKAGE_FILE 和 COMPILE_INFO_PDF

### 5. 新增端点

- `TenderDocumentController` 新增 `POST /recompile?tenderDocumentId=`

### 6. 测试

- 更新 `TenderDocumentServiceTest`：
  - entry 命中 DRAFT → 复用
  - entry 命中 COMPLETED → 原样返回
  - entry 命中 GENERATING 超时 → 重置
  - entry 命中 GENERATING 未超时 → 原样返回
  - entry 超时且存在 PROCESSING 记录 → 标记失败
  - recompile 正常流程
  - recompile 失效旧产物
  - recompile 非 COMPLETED 拒绝

### 7. 回归验证

- `mvn -pl ele-tender-tender-document -am test` 全量通过
