# 2026-03-23 检查项接口真实校验实施计划

## 实施步骤

### 1. 重写 getCheckItems 方法
- 文件：`TenderDocumentStepServiceImpl.java`
- 将占位循环替换为 4 个独立的 private 检查方法调用：
  - `checkBasicInfo(doc, userContext)` — 调 syncGateway 拉最新数据，计算 hash 与快照 source_hash 比对
  - `checkPurchaseFile(doc)` — 查 td_tender_document_file 表 SIGNED_PDF + activeFlag=1
  - `checkBidRecord(doc, userContext)` — 同 checkBasicInfo 策略，拉标录数据比对 hash
  - `checkEvaluationRule(doc)` — 复用 validateEvaluationRules，捕获 BusinessException 转为 message
- 每个方法内部 try-catch，保证单项异常不影响整体返回。
- 辅助方法 `buildCheckItemView(stepCode)` 统一构建检查项视图对象。

### 2. 补充单元测试
- 文件：`TenderDocumentStepServiceTest.java`
- 新增 8 个测试用例：
  - BASIC_INFO：hash 一致通过、hash 不一致失败、快照缺失失败、syncGateway 异常失败
  - PURCHASE_FILE：SIGNED_PDF 存在通过、不存在失败
  - EVALUATION_RULE：规则校验通过、规则未配置失败

### 3. 回归验证
- `mvn -pl ele-tender-tender-document -am clean test`
- 确认全部 148 个测试通过，无回归。

## 风险与控制
- 风险：checkBasicInfo / checkBidRecord 会实时调用 syncGateway，若业务系统不可达会导致检查项返回异常提示。
- 控制：每个检查方法内部 try-catch 隔离，即使 syncGateway 超时也只影响对应检查项，不阻塞其他项。
