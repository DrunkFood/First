# DTO 单源 + 显式映射 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 以 `common-interaction` 为协议 DTO 单源，在 `support` 侧通过 mapper 显式转换到内部模型，并补充项目级设计说明。

**Architecture:** 协议边界层仅负责接收/返回交互 DTO，业务服务层改用内部命令对象；校验逻辑从注解驱动迁移为显式代码校验，降低对宿主 Bean Validation 生态差异的耦合。

---

### Task 1: 先写失败测试锁定 mapper 行为

- 新增 mapper 单测：覆盖“成功映射”和“必填字段缺失时报错”。
- 先跑测试确保失败（类不存在或行为未实现）。

### Task 2: 落地单源+显式映射

- `common-interaction`：去掉 `jakarta.validation-api` 依赖与注解。
- `support`：新增内部命令模型与 mapper，`Controller` 层执行显式映射和校验。
- `Service`：改为接收内部命令对象，避免业务层直接依赖协议请求 DTO。

### Task 3: 更新项目说明

- 在 `AGENTS.md` 增加原则条目。
- 在项目说明文档中补充：
  - 设计动机
  - 实操指导
  - 数量增多时的演进路线（例如抽 `common-model`）。

### Task 4: 验证

- 运行 mapper 单测。
- 运行最小相关模块编译与测试命令，确认无编译回归。
