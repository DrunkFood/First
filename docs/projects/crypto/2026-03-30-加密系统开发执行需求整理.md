- 交互协议层：crypto DTO/SPI、路径常量、校验扩展（JDK8 兼容）。
- interaction starter：crypto client 与 callback 控制器扩展。
- 新服务：新增 `ele-tender-crypto` 模块及主链路（push/submit/status、stream 消费、回调）。
- 支撑中心：crypto 管理查询与人工重试能力。
- 前端：新增 `/crypto-api` 代理。
- 发布：版本统一到 `2.0.0`，并与功能提交隔离。

## 3. 约束与默认策略

- 规范基线：
  - `docs/projects/ELE_TENDER_CRYPTO_SPEC.md`
  - `docs/plans/2026-03-30-crypto-module-development-plan.md`
- 按 AGENTS 约束执行：
  - 统一 `Result<T>` 响应。
  - 统一全局异常处理。
  - 鉴权注解与权限注解按模块约束使用。

## 5. 2026-03-31 Code Review 收敛

### 5.1 本次直接实施的三项修复

- 指纹算法修复：
  - `CryptoFingerprintUtil` 现状仅对 `bidderPwdStr` 做 `sha256Hex`，未纳入 `crypto.bidderPwdFingerprintSecret`。
  - 本次调整为带 secret 的稳定指纹算法，并同步修正对应测试。
- 文件落盘路径修复：
  - `BidDocumentServiceImpl` 当前落盘路径为 `{bidDocumentPath}/{appKey}/{sha256}.HzctTbs`。
  - 本次按规范补齐三级子目录后再落盘，并补路径断言测试。
- `file_id` 类型修复：
  - `bdc_bid_document.file_id`、`BdcBidDocument.fileId` 以及 bid-document push/callback 协议 DTO 当前仍为 `Long/bigint`。
  - 本次保持 `Long/bigint` 不变，撤回字符串化调整，确保与文件服务真实契约一致，并同步修正校验与回调链路。

### 5.2 本次不直接改动的争议项

- Stream ACK：
  - `DecryptTaskStreamConsumer` 当前 `finally` 无条件 ACK 属于现有设计，不按“遗漏 ACK”处理。
  - 后续单独评估“异常时状态未成功落库导致消息丢失窗口”的问题。
- 超时与密码缓存：
  - 默认配置 `taskTimeoutSeconds=1800`、`passwordCacheSeconds=3600` 下，不存在“必然超时重试失败”。
  - 后续如需增强，仅考虑补参数约束或配置校验。
- 去重竞态与唯一键：
  - `BidDocumentServiceImpl` 查重维度是 `(app_key, file_id)`，DDL 尚无对应唯一键。
  - 由于 artifact 复用维度是 `(app_key, file_sha256, bidder_pwd_fingerprint)`，本次不直接加唯一键，待业务语义确认后再定。
- `retryRequest` 重复回调：
  - 现有代码只会处理 `PENDING/PROCESSING` request，原“会触发其他 request 重复回调”的结论不成立。
  - 本次不围绕该结论做行为修改，仅保留人工重试语义确认事项。
