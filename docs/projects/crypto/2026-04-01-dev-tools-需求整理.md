# 开发联调 CLI 工具需求整理

> 日期：2026-04-01
> 状态：已完成

---

## 背景

开发和联调阶段需要频繁手工生成招标文件（`.HzctZbs`）和投标文件（`.HzctTbs`），以及手工解密它们来验证内容。现有工具分散在不同模块，缺少统一入口：

| 现有工具 | 所在模块 | 能力 | 缺陷 |
|---------|---------|------|------|
| `FinalPackageCryptoCli` | `ele-tender-tender-document` | AES-GCM 加解密本地文件 | 不生成 mock 数据；不覆盖投标文件 |
| `NativeVectorExportCli` | `ele-tender-crypto` | 生成投标文件测试向量 | 只能生成，不能解密；密码固定 |

---

## 需求

1. **生成 mock 招标文件**：自动构造样例 `FinalPackagePayload`，AES-GCM 加密 → `.HzctZbs` 文件，输出明文 JSON + 密文 + manifest
2. **生成 mock 投标文件**：构造样例 bid document，使用 `ICryptoNative`（stub/native 自动降级）加密 → `.HzctTbs`，输出明文 + 密文 + manifest
3. **解密招标文件**：`.HzctZbs` + AES key → 明文 JSON
4. **解密投标文件**：`.HzctTbs` + 投标人密码 → 明文 bid document JSON + project info JSON
5. **统一 CLI 入口**：四个功能通过子命令 `generate-tender / generate-bid / decrypt-tender / decrypt-bid` 调用
6. **无需 Spring 上下文**：直接 `java -cp` 或 `mvn exec:java` 运行
7. **stub 模式透明降级**：native lib 不可用时自动降级，打印警告

---

## 约束

- 不修改 `ele-tender-crypto` 或 `ele-tender-tender-document` 的生产代码
- 不引入新的外部依赖（只复用现有模块中的类）
- 须复用 `FinalPackageCryptoUtil`、`ICryptoNative`/`JniCryptoNative`

---
