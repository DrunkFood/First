# 2026-03-20 业务系统交互全量留痕需求整理

## 背景
- 用户要求：所有与业务系统的交互必须留痕。
- 现状：
  - HTTP 入站日志已由公共过滤器落库到 `sup_access_log`。
  - `tender-document` 调业务系统的出站调用主要在 `BusinessSystemRemoteClient`，此前以控制台日志为主。

## 目标
- 对 `tender-document -> 业务系统` 的交互实现成功/失败全量落库。
- 留痕字段满足按 `traceId/appKey/bizType/bizId/projectId/tenderId/fileId` 检索。
- 敏感信息脱敏（token/signature）。

## 存储方案
- 统一落 `sup_access_log`，`log_type=INTERACTION_OUT`。
- 业务状态表（如回传记录）继续用于业务语义，不替代审计留痕。

## 验收标准
- 出站调用成功时落库一条 `INTERACTION_OUT`。
- 出站调用失败（含协议失败、网络异常）时也落库一条 `INTERACTION_OUT`，包含错误信息。
- 单测可验证落库调用发生且关键字段正确。
