# 2026-03-19 回传联调变更说明（发业务系统）

## 1. 本次变更结论

- 电子标系统与业务系统的**回调协议未变**（路径、字段、签名头不变）。
- 电子标系统统一回传接口 `POST /api/tender-documents/generate/callback` 的行为收口为：
  - 两类文件分别回传：`SIGNED_PDF`、`FINAL_PACKAGE_FILE`
  - 任一类失败时返回“部分失败”，不会整批中断
  - 回传历史按文件类型独立留痕，保留重试次数

## 2. 对业务系统的影响

### 2.1 不需要改的

- 不需要改固定回调接口路径：
  - `POST /api/eleTender/interaction/callbacks/tender-pdf`
  - `POST /api/eleTender/interaction/callbacks/tender-package`
- 不需要改回调请求字段：
  - `bizType`、`bizId`、`projectId`、`tenderId`、`fileId`、`fileName`
- 不需要改签名校验协议：
  - `X-App-Key`、`X-Timestamp`、`X-Signature`

### 2.2 建议确认的

- 业务系统回调处理应支持“部分失败后单项重试”。
- 业务系统应继续按 `fileId` 做闭环：
  1. 回调落库业务键 + `fileId`
  2. 查询文件信息（`getFileInfo`）
  3. 下载文件流（`downloadFile`）

## 3. 前端联调口径（需同步）

- 对统一回传接口，不能只看外层 `code`，要看 `data.success`：
  - `data.success=true`：回传完成
  - `data.success=false`：回传部分失败，需要提示重试
- 子结果字段以 `responseCode`、`responseMessage`、`retryCount` 为准。

## 4. 联调验收清单（建议）

- 回调接口可正常接收并验签通过
- 能按 `fileId` 查询文件信息
- 能按 `fileId` 下载文件内容
- 业务系统对重复回调具备幂等处理
- 统一回传“部分失败”场景下可引导单项重试

## 5. 风险提示

- 若业务系统在回调 SPI 中“吞异常并标记成功”，会掩盖真实失败，导致后续无法追踪重试。
- 建议至少记录：`traceId`、`bizType`、`bizId`、`projectId`、`tenderId`、`fileId`、失败原因。
