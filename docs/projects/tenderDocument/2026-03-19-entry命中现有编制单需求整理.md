# 2026-03-19 entry命中现有编制单需求整理

## 背景

在相同业务维度（`bizType + bizId + projectId + tenderId(按compileScope需要)`）下，数据库存在多条历史编制单版本。
现网 `entry` 逻辑在“没有 DRAFT”时会新建草稿，导致相同业务维度持续产生新草稿版本。

## 当前问题

- `PROJECT` 范围下不使用 `tenderId` 参与匹配是正确的，不需要修改。
- 问题在于：同一业务维度已存在编制单时，`entry` 仍可能新建草稿，而不是加载已有编制单。

## 目标行为

`POST /api/tender-documents/entry` 命中规则调整为：

1. 先命中同维度 `DRAFT`：命中则返回该草稿（保持现有行为）。
2. 若无 `DRAFT`，再命中同维度最新编制单（通常为 `COMPLETED`）：命中则直接返回，不新建草稿。
3. 仅当同维度完全无编制单时才创建新草稿并初始化步骤。

## 影响范围

- 后端模块：`ele-tender-tender-document`
- 代码：`TenderDocumentServiceImpl.enter`
- 测试：`TenderDocumentServiceTest`

## 验收点

- 已有 `COMPLETED` 且无 `DRAFT` 时：`entry` 返回已有编制单 `id`，不执行 `insert`。
- 已有 `DRAFT` 时：仍命中 `DRAFT`。
- 完全无记录时：仍创建新草稿。
