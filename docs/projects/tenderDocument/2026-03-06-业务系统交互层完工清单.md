# 业务系统交互层完工清单

## 1. 目的

本文档用于整理当前仓库中“电子标系统与业务系统交互层”的完成情况、剩余缺口与完工验收项，作为后续开发与联调的跟踪依据。

## 2. 当前结论

基于当前代码核查结果，可以得出以下结论：

- `ele-tender-common-interaction`、`ele-tender-interaction-core`、`ele-tender-interaction-autoconfigure`、`ele-tender-interaction-spring-boot-starter` 已基本开发完成。
- 上述模块已经具备协议 DTO、SPI、签名规则、固定入站接口、出站 client、自动装配与基础测试能力。
- 但电子标系统内部 `ele-tender-tender-document` 与真实业务系统之间的正式交互闭环尚未完成。
- 当前 `tender-document` 中的同步、生成、回传仍存在默认占位实现，不能认定为“与业务系统交互层已开发完毕”。

结论归纳：

- 如果判断对象是“交互协议/starter 框架”，则基本完成。
- 如果判断对象是“真实业务系统交互闭环”，则尚未完成。

## 3. 已完成项

### 3.1 交互协议与公共模型

- 已提供交互接口路径常量。
- 已提供交互请求头常量。
- 已提供统一返回结构 `InteractionResult<T>`。
- 已提供外部 token、当前用户、项目基本信息、标录方案、文件信息、文件下载、回调请求等协议 DTO。
- 已提供签名工具与基础参数校验工具。

### 3.2 starter 出站能力

- 已提供获取电子标外部 token 的 client。
- 已提供获取当前外部用户信息的 client。
- 已提供按 `fileId` 查询文件信息的 client。
- 已提供按 `fileId` 下载文件的 client。
- 已提供招标文件编制页跳转地址构造器。

### 3.3 starter 入站能力

- 已提供固定路径的标准 controller：
  - `GET /api/eleTender/interaction/identity/current`
  - `POST /api/eleTender/interaction/projects/basic-info`
  - `POST /api/eleTender/interaction/bid-record-schemes/query`
  - `POST /api/eleTender/interaction/callbacks/tender-pdf`
  - `POST /api/eleTender/interaction/callbacks/tender-package`
- 已提供基于 `X-App-Key`、`X-Timestamp`、`X-Signature` 的统一签名校验拦截器。
- 已提供自动装配能力，业务系统实现 SPI 后即可按约定暴露接口。

### 3.4 电子标系统已有支撑能力

- `ele-tender-support` 已提供 `/api/external/token`、`/api/external/userinfo` 等外部认证能力。
- `tender-document` 已抽象出同步网关、生成网关、回传网关，说明交互扩展点已预留。

## 4. 未完成项清单

### 4.1 电子标系统侧缺口

- [ ] 用正式实现替换 `DefaultTenderDocumentSyncGateway`，不能继续返回“示例项目”“示例标段”等占位数据。
- [ ] 用正式实现替换 `DefaultTenderDocumentGenerationGateway`，生成逻辑需要接真实生成服务或文件服务，不能只本地伪造 `fileId`、`sha256` 和文件大小。
- [ ] 用正式实现替换 `DefaultTenderDocumentCallbackGateway`，回传必须真实调用业务系统，而不是固定返回成功。
- [ ] 在 `ele-tender-tender-document` 中接入正式出站调用能力，完成对业务系统接口的真实访问。
- [ ] 为同步、生成、回传链路补齐明确的异常码、失败原因透传和统一错误处理。
- [ ] 为交互链路补齐可追踪日志，确保 `traceId`、`bizType`、`bizId`、`projectId`、`tenderId`、`fileId` 能串联定位。

### 4.2 业务系统侧缺口

- [ ] 引入 `ele-tender-interaction-spring-boot-starter`。
- [ ] 实现 `InteractionIdentityService`。
- [ ] 实现 `InteractionProjectInfoService`。
- [ ] 实现 `InteractionBidRecordSchemeService`。
- [ ] 实现 `InteractionTenderPdfReceiveService`。
- [ ] 实现 `InteractionTenderPackageReceiveService`。
- [ ] 配置 `ele-tender.interaction.base-url`、`app-key`、`app-secret`、`file-base-url` 等关键配置。
- [ ] 确认业务系统最终暴露的固定接口路径与 starter 约定保持一致。

### 4.3 协议与契约缺口

- [ ] 确认 `ProjectBasicInfoResponse` 稳定返回 `projectType`。
- [ ] 优先确认 `ProjectBasicInfoResponse` 同时返回 `compileScope`。
- [ ] 确认 `compileScope` 固定只使用 `PROJECT` / `TENDER`。
- [ ] 确认 `tenderAmount` 的语义固定为“标段标的金额”。
- [ ] 确认回传中的 `fileId` 为文件引用，业务系统能再基于 `fileId` 查询信息并下载文件。
- [ ] 确认电子标系统与业务系统双方的签名算法、请求头命名和时间戳规则保持一致。

## 5. 联调验收清单

### 5.1 入口与基础信息

- [ ] 业务系统可成功调用电子标系统 `/api/external/token`。
- [ ] 业务系统可基于 token 正确构造招标文件编制页跳转地址。
- [ ] 电子标系统 `POST /api/tender-documents/entry` 可真实拉取业务系统项目基本信息。
- [ ] 基本信息页“同步最新数据”可真实刷新业务系统数据，而不是复用本地假数据。

### 5.2 业务数据同步

- [ ] 开标标录页可真实拉取业务系统标录方案。
- [ ] 公开类项目能按项目级完成数据同步与文件绑定。
- [ ] 邀请类项目能按标段级完成数据同步与文件绑定。

### 5.3 文件生成与回传

- [ ] 生成完成后，电子标系统可真实生成数据包并落业务绑定记录。
- [ ] 生成完成后，电子标系统可成功回传签章 PDF。
- [ ] 生成完成后，电子标系统可成功回传电子标数据包。
- [ ] 回传失败时可记录真实失败结果、失败码和重试次数。
- [ ] 业务系统收到回传后，可基于 `fileId` 查询文件信息并下载文件。

### 5.4 观测与审计

- [ ] 双方日志可以通过同一条 `traceId` 串起来。
- [ ] 失败链路可以明确定位是签名失败、参数错误、业务校验失败还是文件访问失败。
- [ ] 关键回传动作有可查询的历史记录，不覆盖历史结果。

- [ ] 补“电子标系统真实调用业务系统”的集成测试。

- [ ] 补签名错误、参数缺失、项目数据缺失、文件不存在、回传失败等异常场景测试。
- [ ] 执行最小联调用例并记录结果。
- [ ] 更新交互接入文档与 OpenAPI 说明。
- [ ] 确认 starter 制品具备可发布、可版本化的交付方式。

## 7. 完工判定标准

满足以下条件后，才建议认定“业务系统交互层已开发完毕”：

1. 交互协议/starter 框架可稳定使用。
2. `ele-tender-tender-document` 不再依赖默认占位实现。
3. 业务系统 5 个 SPI 已完成真实实现。
4. 入口、基本信息同步、标录同步、文件回传全链路真实跑通。
5. 成功、失败、重试、审计、日志追踪都具备可验证结果。

## 8. 建议的推进顺序

建议按下面顺序推进，避免后面返工：

1. 先确定协议字段和签名规则。
2. 再完成业务系统 5 个 SPI 的真实实现。
3. 再替换电子标系统中的 3 个默认 Gateway 实现。
4. 然后完成入口、同步、生成、回传四条主链路联调。
5. 最后补齐异常测试、日志审计和交付文档。

## 9. 本次核查结论摘要

本仓库当前状态更准确的描述应为：

- “交互 starter 与协议层已具备交付基础”
- “电子标系统与真实业务系统的正式交互闭环仍未完工”

因此，现阶段不建议对外宣称“和业务系统的交互层已经全部开发完毕”。
