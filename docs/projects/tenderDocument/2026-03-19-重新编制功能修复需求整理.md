# 2026-03-19 重新编制功能修复需求整理

## 背景

招标文件编制单完成生成后进入 `COMPLETED` 状态。用户在结果页点击"重新编制"后，期望能重新生成文件，但后端 `assertGenerationAllowed` 拒绝 `COMPLETED` 状态（error 6020），导致无法重新生成。

根因：原 `entry` 的 `findExistingDocument` 不区分状态，命中 `COMPLETED` 后直接返回，前端拿到的是已锁定的编制单；而生成接口又拒绝 `COMPLETED`，形成死锁。

## 需求目标

### 1. entry 逻辑调整

- 同维度取最新版本编制单（`versionNo DESC`，不区分状态）
- `DRAFT` → 刷新 sync 数据，返回
- `COMPLETED` → 原样返回（前端展示结果页 + "重新编制"按钮）
- `GENERATING` 超时（默认 1800 秒，可配置）→ 重置为 `DRAFT`，标记残留的 `PROCESSING` 生成记录为失败
- `GENERATING` 未超时 → 原样返回
- 无记录 → 创建首版 `DRAFT`（`versionNo = 1`）

### 2. 新增 recompile 端点

`POST /api/tender-documents/recompile?tenderDocumentId={id}`

- 仅 `COMPLETED` 状态允许重新编制，否则抛 6021
- 原地重置：`status → DRAFT`，`versionNo + 1`
- `currentStepCode` 保持 `GENERATE_PACKAGE`
- `GENERATE_PACKAGE` 步骤状态回退为 `IN_PROGRESS`，其余步骤保持 `COMPLETED`
- 失效旧产物文件（`FINAL_PACKAGE_FILE`、`COMPILE_INFO_PDF`），保留 `SIGNED_PDF` 和 `PURCHASE_SOURCE_PDF`

### 3. 生成接口

无需修改。recompile 后编制单为 `DRAFT`，正常走 `generate()` 流程。

## 影响范围

- `TenderDocumentServiceImpl`（entry 逻辑 + 新增 recompile）
- `ITenderDocumentService`（新增方法签名）
- `TenderDocumentController`（新增端点）
- `TenderDocumentErrorCode`（新增 6021）
- `application.yml`（新增 `generation-timeout-seconds`）
- `TenderDocumentServiceTest`（覆盖 entry 各状态分支 + recompile 场景）

## 验收点

- `COMPLETED` 状态调用 entry → 原样返回（不新建、不刷新 sync）
- `COMPLETED` 状态调用 recompile → 状态变为 `DRAFT`，`versionNo` 递增，旧产物失效
- recompile 后调用 generate → 正常生成新版本
- `GENERATING` 超时调用 entry → 自动重置为 `DRAFT`
- `GENERATING` 未超时调用 entry → 原样返回 `GENERATING`
- 非 `COMPLETED` 状态调用 recompile → 拒绝（6021）
