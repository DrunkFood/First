# 2026-03-05 DTO 单源 + 显式映射需求整理

## 1. 需求

采用“单源 + 显式转换（mapper）”方案，避免在 `common` 与 `common-interaction` 维护同名同义双份 DTO。

## 2. 本次目标

1. 代码层面落地：
   - 交互协议 DTO 保持单源。
   - 业务实现层通过 mapper 做显式转换，不依赖 Bean Validation 注解驱动校验。
2. 文档层面沉淀：
   - 在项目说明中明确该设计的原因、适用规则、以及后续扩展方案。

## 3. 验收

- `common-interaction` 不再依赖 Bean Validation 注解。
- `support` 外部认证链路完成“协议 DTO -> 内部模型”的 mapper 转换。
- 项目说明新增指导意见：
  - 为什么这么做
  - 下次遇到相同问题如何处理
  - 当类似情况增多时的演进方案
