# 2026-03-23 检查项接口真实校验需求整理

## 背景
- 接口 `GET /api/tender-documents/check-items` 当前为占位实现，所有检查项固定返回 `passed=false, message="一期暂不校验"`。
- 需要接入真正的业务校验逻辑，在用户进入「检查项」步骤时给出各环节的真实检查结果。

## 现状
- 控制器和 DTO 结构已就绪（`TenderDocumentStepController`、`TenderDocumentCheckItemsResponse`、`TenderDocumentCheckItemView`）。
- 各步骤的数据存储和同步机制已完备（快照表 + syncGateway + 文件绑定表 + 评审规则校验器）。
- 只缺 `getCheckItems` 方法内部的真实判断逻辑。

## 需求明细

### 1. BASIC_INFO — 检查项目基本信息是否有更新
- 通过 `TenderDocumentSyncGateway.syncBasicInfo()` 拉取业务系统最新数据。
- 将结果序列化后计算 SHA-256 hash，与 `td_tender_document_snapshot` 中已存储的 `source_hash` 比对。
- hash 一致 → 通过；hash 不一致 → 不通过，提示重新同步。
- 快照不存在 → 不通过，提示尚未同步。
- 此处只做**读取比对**，不更新快照。

### 2. PURCHASE_FILE — 检查签章文件是否存在
- 查询 `td_tender_document_file` 表：`fileRole=SIGNED_PDF` + `activeFlag=1`。
- 存在 → 通过；不存在 → 不通过。
- 不检查 `PURCHASE_SOURCE_PDF`（源采购文件）。

### 3. BID_RECORD — 检查开标标录信息是否有更新
- 与 BASIC_INFO 相同策略：拉最新标录数据，计算 hash 与快照比对。

### 4. EVALUATION_RULE — 检查评审规则总分是否匹配
- 复用已有的 `validateEvaluationRules` 完整校验（含必填分类检查 + 综合评分法跨分类约束）。
- 无异常 → 通过；捕获 `BusinessException` → 不通过，展示异常消息。

## 验收标准
- 4 个检查项各自独立：单项异常不影响其他项正常返回。
- 各场景（通过 / hash 不一致 / 快照缺失 / syncGateway 异常 / 规则校验失败）均有单测覆盖。
- `mvn -pl ele-tender-tender-document -am clean test` 全部通过。
