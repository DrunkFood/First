# 最终数据包 AES 加密需求整理

## 背景

- 当前最终招标文件数据包的“加密”为占位实现（`ENC:` + Base64 明文），不满足真实加密诉求。
- 业务确认本阶段不需要双锁信封方案，采用对称加密即可。

## 本次目标

- 将最终数据包加密改为 `AES-GCM`。
- 继续保留文件后缀可配置能力（默认 `.HzctZbs`）。
- 生成的加密文件为二进制内容，不再是明文可读 JSON。

## 约束与假设

- 不改动回传流程和文件角色模型。
- 仅替换 `FinalPackageEncryptor` 默认实现。
- AES 密钥从配置读取，默认提供开发环境值，生产环境通过外部配置覆盖。

## 验收标准

- 加密结果非空，且不包含明文 JSON 片段。
- 可通过同一密钥解密还原原始 JSON（单测验证）。
- 现有生成链路相关测试保持通过。
