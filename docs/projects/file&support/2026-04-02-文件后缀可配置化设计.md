# 招标/投标文件后缀可配置化设计

## 背景

当前 `.HzctZbs`（招标文件）和 `.HzctTbs`（投标文件）后缀在多个模块中硬编码。不同接入系统可能需要使用不同的文件后缀，需要按接入系统粒度配置。

## 方案

在现有 `sup_access_system` 表上新增两个字段，各模块通过已有的 `selectByAppKey` 查询获取后缀。字段为空时回落到默认值。

## 数据模型

### 表变更

```sql
ALTER TABLE sup_access_system
  ADD COLUMN tender_document_suffix VARCHAR(32) DEFAULT NULL COMMENT '招标文件后缀(如.HzctZbs)',
  ADD COLUMN bid_document_suffix VARCHAR(32) DEFAULT NULL COMMENT '投标文件后缀(如.HzctTbs)';
```

### 实体变更

`SysAccessSystem` 新增：

```java
private String tenderDocumentSuffix;  // 招标文件后缀
private String bidDocumentSuffix;     // 投标文件后缀
```

### 默认值常量

`ele-tender-common` 新增 `FileConstants`：

```java
public final class FileConstants {
    public static final String DEFAULT_TENDER_DOCUMENT_SUFFIX = ".HzctZbs";
    public static final String DEFAULT_BID_DOCUMENT_SUFFIX = ".HzctTbs";
}
```

## 后端模块改造

### tender-document 模块

**后缀来源**：`TenderDocumentGenerationServiceImpl.generate()` 中通过 `userContext.getAppKey()` 查 `SysAccessSystem`，取 `tenderDocumentSuffix`，为空回落到 `FileConstants.DEFAULT_TENDER_DOCUMENT_SUFFIX`。

**接口变更**：`TenderDocumentGenerationGateway.saveFinalPackage()` 新增 `String suffix` 参数。

**影响的实现类**：
- `InteractionTenderDocumentGenerationGateway` — 使用传入的 suffix 替代 `properties.getFinalPackageSuffix()`
- `DefaultTenderDocumentGenerationGateway` — 使用传入的 suffix 替代硬编码的 `.HzctZbs`

### crypto 模块

**后缀来源**：通过 `SysAccessSystemReadMapper.selectByAppKey(appKey)` 查后缀，为空回落到 `FileConstants.DEFAULT_BID_DOCUMENT_SUFFIX`。

**影响的类**：
- `BidDocumentServiceImpl.persistEncryptedFile()` — `fileSha256 + suffix`
- `OrganizedFileCopyService.copyEncryptedFile()` — `bidRecordId + suffix`

### file 模块

`allowed-types` 保持 yml 配置，部署时手动维护。不做动态查询。

### dev-tools 模块

新增 `DevToolsConstants` 常量类，替换代码逻辑中的字面量。注释和帮助文本保留原样。

## 前端改动

### 接入系统编辑表单

在新增/编辑对话框中加两个 `el-input` 字段：
- **招标文件后缀** (`tenderDocumentSuffix`) — placeholder: `.HzctZbs`，非必填
- **投标文件后缀** (`bidDocumentSuffix`) — placeholder: `.HzctTbs`，非必填

不在列表中展示后缀字段。

### 类型定义

`ExternalSystem` 接口和请求参数 DTO 中加对应字段。

## 回落机制

```
接入系统配置的后缀 → 为空 → FileConstants 默认值（.HzctZbs / .HzctTbs）
```

## 不改动的部分

- `file` 模块 `allowed-types` — 部署时手动维护
- `NativeVectorExporter` — 导出测试向量工具，独立运行
- 文档/注释中的后缀引用 — 描述性文本
- `TenderDocumentInteractionProperties.finalPackageSuffix` — 保留但不再作为主要后缀来源

## 验证方式

1. `mvn clean test` 全量测试通过
2. 前端创建接入系统时设置自定义后缀 → 生成招标/投标文件 → 确认文件名使用自定义后缀
3. 接入系统后缀字段为空 → 确认回落到默认值
