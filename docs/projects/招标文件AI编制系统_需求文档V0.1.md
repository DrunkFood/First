# 招标文件AI编制系统 - 业务需求文档

## 一、系统概述

### 1.1 系统定位
招标文件AI编制系统是一套AI驱动的智能招标文件编制工具，旨在通过AI技术辅助招标人员高效完成招标文件的编制、审核和发布工作。系统既是AI应用展示载体，也是业务流程重构工具。

### 1.2 建设目标
- 初期目标：快速实现"有AI"，接受渐进式优化，预计一年左右达到稳定可用水平
- 核心目标：实现招标文件编制流程的智能化，减少人工编制工作量，提高文件质量

### 1.3 部署模式
- **独立运行版本**：当前阶段，系统作为独立产品运行
- **嵌入模式**：后续可嵌入第三方招标平台（如招必得）
- **一体机模式**：可单独销售的一体化解决方案

## 二、核心功能模块

### 2.1 用户认证模块

#### 2.1.1 登录方式
- 手机号 + 验证码免注册直登
- 与招必得用户体系打通

#### 2.1.2 权限体系
- **用户端**：项目管理、业务需求编制
- **管理端**：模板管理、知识库管理、统计分析
- 两套权限体系独立管理

---

### 2.2 项目管理模块

#### 2.2.1 项目列表
- 支持按项目名称/编号、状态、类别、类型、创建时间筛选
- 展示项目编号、名称、类别、类型、预算、完成进度、创建时间
- 支持批量操作（选中、删除）

#### 2.2.2 项目创建
- **基本信息录入**：
  - 项目名称（必填，1-100字符）
  - 项目类别：限额以下、产权交易、政府采购
  - 项目类型：工程类、货物类、服务类（含物业、IT服务、咨询服务、维保服务）
  - 项目预算（万元）
  - 评审类型：人工评审/智能评审（系统根据预算和类型自动推荐）

- **招标需求获取**（两种模式）：
  - **模式1 - 引用**：
    - 来源A：选择已定稿的编制业务需求模块项目
    - 来源B：直接录入招标需求内容
  - **模式2 - 系统生成**：
    - 用户输入项目描述
    - AI根据项目描述自动生成招标需求

#### 2.2.3 项目初始化
- 完成项目基础信息输入
- 选择适用的招标文件模板
- 自动匹配或手动选择评审类型

#### 2.2.4 项目详情
- **基本信息Tab**：展示项目完整信息、使用模板、评审类型等
- **文档信息Tab**：
  - 展示生成的招标文件
  - 展示引入的业务需求初稿及来源
  - 展示文档结构（招标公告、投标人须知、评标办法、合同条款等）
- **项目进度Tab**：时间轴形式展示项目各阶段进度
- **版本管理Tab**：
  - 版本历史记录
  - 版本查看
  - 版本对比（差异高亮显示：新增、修改、删除）
  - 导出对比报告

#### 2.2.5 项目编辑
- 支持编辑项目基本信息
- 支持修订招标需求内容

#### 2.2.6 项目集成
- 文档生成完成后，支持回传至交易系统
- 支持预览、导出Word格式文档

#### 2.2.7 项目状态流转
草稿 → 进行中 → 待检测 → 检测中 → 检测通过/不通过 → 已发布 → 已归档

---

### 2.3 业务需求编制模块

#### 2.3.1 业务需求列表
- 支持按项目名称、状态、项目类型、创建时间筛选
- 展示项目名称、类型、预算、需求状态、完成进度、创建时间
- 状态包括：草稿、进行中、待检测、检测中、检测通过、检测不通过、已发布、已归档、已取消

#### 2.3.2 业务需求创建
- **基本信息录入**：
  - 需求名称（必填，1-100字符）
  - 项目类别：限额以下、产权交易、政府采购
  - 项目类型：工程类、货物类、服务类（含二级分类）
  - 预算价（万元）
  - 需求描述（选填，≤500字符）

- **历史业务需求匹配**（三种模式）：
  - **模式1 - 系统自动匹配**：
    - 系统基于历史招标文件知识库自动匹配高相关度模板
    - 自动生成业务需求初稿
  - **模式2 - 手动选择**：
    - 展示历史文件库中匹配度高的文件列表
    - 显示匹配度百分比和相似度说明
    - 支持预览和单选
  - **模式3 - 上传**：
    - 支持上传Word格式文件（.doc/.docx，≤50M）
    - 仅可上传1份文件

#### 2.3.3 业务需求生成
- AI基于模板/历史记录/上传文件自动生成业务需求初稿
- 生成过程支持进度条展示（采用"假进度+真功能"策略）
- 生成后支持人工编辑

#### 2.3.4 业务需求编辑
- 支持对AI生成的业务需求进行编辑修订
- 集成AI助手功能：选中文本段落进行交互式优化
  - 例如："优化项目概况描述"
  - 支持局部覆盖式修改
- 支持一键接收全部AI建议（自动修订原文）

#### 2.3.5 业务需求审核
- 支持业务需求的审核流程
- 审核通过后方可进入下一环节

---

### 2.4 智能检测模块

#### 2.4.1 检测功能
- **公平竞争检测**：检测是否存在歧视性条款
- **合规性检查**：检测是否符合相关法律法规
- **错别字检查**：检测文本中的错别字
- **敏感词检测**：
  - 敏感词库内嵌并实时校验
  - 包含领导人称谓等敏感内容
  - 强制脱敏处理（隐藏项目名称、预算金额等）

#### 2.4.2 检测机制
- 基于公有大模型进行检测（复用已有的银行级智能审查能力）
- 用户可自主选择启用或跳过检测
- 检测范围聚焦格式合规性与条款完整性，不涉及业务合理性判断

#### 2.4.3 检测结果
- 以问题清单形式反馈
- 供用户确认或修改
- 检测通过后方可发布

#### 2.8.5 文档发布

## 三、AI模型调用机制

### 3.1 混合模型架构
**"生成用本地模型、修改用大模型"**

| 任务类型 | 使用模型 | 说明 |
|---------|---------|------|
| 生成类任务 | 本地微调大模型 | 标书初稿、评审项、业务需求生成 |
| 内容修改/润色 | 互联网大模型 | 需要强理解与推理的任务 |
| 检测环节 | 公有大模型 | 复用银行级智能审查能力 |

### 3.2 模型支持
- **本地模型**：支持7B/106B基座微调后的推理，不支持训练
- **公有模型**：支持DeepSeek等公有大模型
- **私有模型**：预留接口，未来可接入

### 3.3 调用机制
- 知识库与模型分离
- 公有模型不可直接调用知识库
- 须经中间服务封装后调用
- 支持流式响应（AI助手场景）

### 3.4 成本管控
- 所有外网调用均涉及Token消耗
- 需建立计费机制（如按次收费）
- 做好成本管控

## 四、数据对接

### 4.1 与招必得系统对接
- **单向接口对接**：由招必得主动推送项目基础数据至本系统
- 推送内容：项目名称、类别、预算等
- 避免本系统反向拉取多源数据带来的适配负担

### 4.2 对外输出接口
- 所有对外输出（招标文件、评审办法等）均支持标准化接口导出
- 后续通过标准接口（含统一登录、权限对接、文件输出）快速对接第三方招标平台

## 九、核心业务流程

### 9.1 业务需求编制流程
```
用户录入项目信息 → 系统匹配历史模板/用户上传 → AI生成业务需求初稿 → 人工编辑 → AI助手优化 → 提交审核 → 审核通过
```

### 9.2 招标文件编制流程
```
项目创建 → 基础信息输入 → 选择模板 → 招标需求确认 → 评审项设置 → AI生成招标文件 → 智能检测 → 检测通过 → 发布/回传
```

### 9.3 智能检测流程
```
用户触发检测 → 强制脱敏 → 公平竞争检测 → 合规性检查 → 错别字检查 → 生成问题清单 → 用户确认/修改 → 检测通过/不通过
```
