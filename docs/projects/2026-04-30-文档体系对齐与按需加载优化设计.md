# 文档体系对齐与按需加载优化设计

## 1. 背景与问题

当前 `docs/rules/` + `CLAUDE.md` 存在三类问题：

1. **内容过时**：AI_TENDER_SYSTEM_SPEC.md 中约50%接口路径与实际代码不符
2. **职责混杂**：AI_TENDER_SYSTEM_SPEC 将 core+ai 两个模块揉在一起，CODE_CONVENTIONS 混合前后端规范
3. **内容重复**：PROJECT_SPEC_FINAL 与 CODE_CONVENTIONS 在安全/JWT/链路追踪上重复，CLAUDE.md 与 rules/ 各文件在术语表/接口清单上重复

## 2. 设计原则

- **单一职责**：一个文件 = 一个模块或一个关注点
- **按需加载**：开发某模块时只需加载对应的 1-2 个 spec 文件
- **消除重复**：信息只在一处维护，其他地方通过引用指向
- **代码为准**：文档与代码冲突时以代码为准

### 4.3 DETECTION_FLOW_SPEC.md（新文件）

内容来源与结构：

1. **检测全链路流程图**（mermaid）
   - 提交 → DetectionPhaseTrigger → 4项并行检测 → 汇总 → 状态流转
2. **4种检测类型说明**
   - SENSITIVE_WORD / TYPO / POLICY_REVIEW / FORMAT_CHECK
3. **检测提交与执行**
   - DetectionPhaseTrigger.onEnter() → DetectionService.submit()
   - AiTaskProcessor 轮询 → DetectionEngine 编排 → 4个 Detector 并行
4. **locationRef 自动填充**
   - extractText 获取 segments → fillLocationRefs 匹配每个 issue
   - locationRef 结构：{type, elementIndex, tableIndex?, rowIndex?, cellIndex?}
5. **修复流程**
   - acceptIssue → fixDocument（精准定位 vs 全文档匹配）
   - acceptAll → 批量替换
   - 两级匹配：精确优先 → 规范化兜底
6. **状态流转**
   - DETECTION_FAILED → 全部处理 → 自动 DETECTION_PASSED
   - 检测重试必须走状态机
7. **版本备份**
   - 检测完成时自动创建 tb_project_version 快照
8. **排障指南**
