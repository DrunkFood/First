根目录作为多模块聚合层，将业务域拆分为四个独立 Spring Boot 子服务：ele-ai-tender-core（项目/阶段/评审项主流程）、ele-ai-tender-ai（AI 对话与文档生成处理器）、ele-ai-tender-file（Markdown/Word 文档引擎）、ele-ai-tender-support（系统支撑：用户/角色/模板/知识库/短信网关），并通过共享包 ele-ai-tender-common 暴露统一的 entity/dto/enums/response 契约；前后端分离由两个独立 Vite 应用 ele-ai-tender-frontend（业务前台）与 ele-ai-tender-support-frontend（管理后台）分别调用对应服务的 REST API。

跨子服务通信采用两种模式：
- 同步 HTTP：core/ai/file/support 各自暴露 Controller，通过 Spring Web 互相调用（如 core 调用 file 的文档转换接口）。
- SPI 扩展：ele-ai-tender-interaction 提供 interaction-spi 定义消息通道、事件模型与插件接口，interaction-core 提供默认实现，各业务模块通过 spring-boot-starter 自动装配接入，使 AI 聊天、消息推送等能力可插拔。

所有 Java 子模块在 ele-ai-tender-system/pom.xml 中声明依赖关系，common 被其余四服务共同引用，形成单向依赖环：core ← common, ai ← common, file ← common, support ← common。

前端侧通过各自的 vite.config.ts proxy 指向不同后端端口，Jenkinsfile-* 为每个子服务定义独立构建/打包/部署流水线，根级 README.md 与 docs/guides/*.yml 提供全局配置入口。
