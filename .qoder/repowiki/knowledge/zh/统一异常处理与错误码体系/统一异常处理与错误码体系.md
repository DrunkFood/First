## 后端异常处理架构

### 核心设计模式
项目采用基于 Spring Boot @RestControllerAdvice 的全局异常处理机制，通过分层异常类型和统一响应格式实现标准化的错误处理。

### 异常类型体系
- 基础异常类：BusinessException、AuthException、FileException 等继承自 RuntimeException，每个异常类都包含 code 字段用于返回错误码
- 领域特定异常：各模块定义专用异常，如 AI 模块的 AiUnavailableException、AiErrorContentException，文件模块的 FileException
- 交互层异常：InteractionException 专门处理跨模块交互错误

### 全局异常处理器
每个服务模块都有独立的 GlobalExceptionHandler，使用 @RestControllerAdvice 注解统一捕获异常：
- 认证异常：AuthException → 401 状态码
- 业务异常：BusinessException → 业务错误码
- 参数校验异常：MethodArgumentNotValidException、BindException → 400 状态码
- 系统异常：兜底捕获 Exception → 通用错误消息

### 统一响应格式
所有错误通过 Result<T> 统一封装，包含：
- code: 错误码（200成功，其他为错误）
- message: 错误消息
- data: 响应数据
- timestamp: 时间戳

### 错误码规范
ResponseCode 枚举定义了完整的错误码体系：
- 通用码：200(成功)、500(失败)
- HTTP状态码：400(参数错误)、401(未授权)、403(禁止访问)
- 业务域码：用户(1001-1999)、权限(2001-2999)、文件(5001-5999)、AI编制(8001-8999)等

## 前端错误处理机制

### Axios 拦截器
双前端项目均采用 Axios 拦截器实现统一的请求/响应处理：

请求拦截器：自动添加 Authorization 头携带 Token
响应拦截器：
- 业务错误码判断：code !== 200 时显示错误提示
- 401 特殊处理：弹出确认框后自动登出并重定向登录页
- 网络错误分类：根据 HTTP 状态码显示不同错误信息
- 超时处理：ECONNABORTED 错误友好提示

### 错误展示策略
- 使用 Element Plus 的 ElMessage.error() 显示错误消息
- 401 错误使用 ElMessageBox.confirm() 弹窗确认
- 支持 blob 响应类型（文件下载）的特殊处理

## 开发规范

### 后端抛错规范
1. 业务异常优先抛出 BusinessException 或领域特定异常
2. 使用 ResponseCode 枚举中的预定义错误码
3. 避免直接抛出 RuntimeException 或 IllegalArgumentException
4. 在 Controller 层使用 @Valid 注解进行参数校验

### 前端错误处理规范
1. 统一通过封装的 request 工具发起请求
2. 在组件中捕获 Promise reject 并做相应处理
3. 区分业务错误和网络错误的处理方式
4. 避免重复的 401 弹窗（已实现防抖机制）

### 异常传播原则
- 控制层：只抛出业务异常，不捕获具体异常
- 服务层：捕获底层异常并转换为业务异常
- 全局处理器：统一格式化响应，隐藏技术细节
