仓库采用「后端聚合根 + 多前端 + 文档/脚本平铺」的多模块结构：ele-ai-tender-system 作为 Maven 聚合根管理 common（共享实体/枚举/异常/工具）、core（项目/阶段/检测/评审主流程）、ai（AI 聊天/知识库/处理器/动态线程池）、file（Markdown→Word/FillData 转换引擎）、support（系统支撑：用户/角色/菜单/短信/外部集成）五个子模块，以及独立的 interaction 子聚合（SPI 契约 + autoconfigure + starter），构成跨模块通信的唯一边界；两个独立前端 ele-ai-tender-frontend（业务编制端）与 ele-ai-tender-support-frontend（管理支撑端）均通过各自 src/api/*.ts 调用同一套后端 REST 接口；数据库初始化集中在 sql/init/ 下按模块拆分（init_core.sql / init_ai.sql / init_file.sql / init_support.sql），与后端模块一一对应；每个后端模块对应一个 Jenkinsfile（Jenkinsfile-core.groovy、Jenkinsfile-ai.groovy、Jenkinsfile-file.groovy、Jenkinsfile-support.groovy 及 web 版），实现统一的构建 → 测试 → 打包 → 部署流水线；docs/rules/ 下的规范文件作为跨模块约定来源约束所有子模块的编码风格与领域模型。
